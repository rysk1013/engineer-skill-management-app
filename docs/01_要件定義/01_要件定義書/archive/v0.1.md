# エンジニアスキル管理アプリ 要件定義書

**Version:** 0.1
**Status:** Draft

---

## 1. 背景・目的

### 1.1 背景

組織に所属するエンジニアが保有している技術・能力を一元的に管理し、組織として社員の技術・能力を把握できる仕組みを構築する。

社員がどのような技術を保有し、どの程度の実務経験・スキルレベルを持っているかを管理することで、社員の技術情報を横断的に確認できる状態を目指す。

### 1.2 主目的

社員の保有技術・能力を把握する。

### 1.3 副目的

- 必要な技術を持つ社員を検索できるようにする
- プロジェクトのアサイン候補を探せるようにする
- 組織全体の技術保有状況を可視化する

- 社員スキル登録
- 社員スキル編集
- 社員スキル無効化
- カテゴリ別スキル表示

#### マスタ管理

- 技術・スキルマスタ管理
- 技術・スキルマスタの名称変更
- 技術・スキルマスタの無効化
- 重複した技術・スキルマスタの統合

#### 検索

- 社員検索

#### 閲覧・集計

## 3. 利用者・権限

### 3.1 権限の種類

初期リリースでは以下の権限を設ける。

1. 管理ユーザー
2. サブマネージャー
3. チームリーダー

一般社員は初期リリースではアプリケーションを利用しない。

権限は社員の実際の役職とは切り離して管理する。

### 3.2 管理ユーザー

管理ユーザーは全社員の情報を閲覧・操作できる。

#### 社員

- 全社員を閲覧できる
- 社員を新規登録できる
- 全社員の社員基本情報を編集できる
- 全社員の在籍状態を変更できる

#### スキル

- 全社員のスキルを閲覧できる
- 全社員のスキルを登録できる
- 全社員のスキルを編集できる
- 全社員のスキルを無効化できる

#### マスタ

- スキルカテゴリを管理できる
- 技術・スキルマスタを追加できる
- 技術・スキルマスタを編集できる
- 技術・スキルマスタを無効化できる
- 重複した技術・スキルマスタを統合できる

#### 検索・集計

- 全社員を対象として検索できる
- 複数スキル検索を利用できる
- 組織全体の集計・ダッシュボードを閲覧できる

### 3.3 権限管理可能な管理ユーザー

管理ユーザーの一部に、権限管理を行う権限を設定できる。

権限管理可能な管理ユーザーは複数人設定できる。

ただし、常に1名以上存在しなければならない。

0名になる操作は禁止する。

#### 権限管理可能な操作

- 管理ユーザー権限の付与・解除
- サブマネージャー権限の付与・解除
- チームリーダー権限の付与・解除
- 権限管理権限の付与・解除
- サブマネージャーへの担当社員の割り当て・解除
- チームリーダーへの担当社員の割り当て・解除

通常の管理ユーザーは上記操作を行えない。

### 3.4 サブマネージャー

サブマネージャーは、割り当てられた担当社員について閲覧・編集できる。

#### 可能な操作

- 担当社員の閲覧
- 担当社員の社員基本情報編集
- 担当社員のスキル閲覧
- 担当社員のスキル登録
- 担当社員のスキル編集
- 担当社員のスキル無効化
- 担当社員を対象とした検索
- 担当社員を対象とした複数スキル検索
- 担当社員を対象とした集計の閲覧

#### 不可能な操作

- 担当外社員の閲覧・編集
- 社員の新規登録
- 社員の在籍状態変更
- 技術・スキルマスタ管理
- スキルカテゴリ管理
- 組織全体の集計閲覧
- 担当社員の割り当て変更
- 権限管理

### 3.5 チームリーダー

チームリーダーは、割り当てられた担当社員について閲覧のみ可能とする。

#### 可能な操作

- 担当社員の社員基本情報閲覧
- 担当社員のスキル閲覧
- 担当社員を対象とした検索
- 担当社員を対象とした複数スキル検索
- 担当社員を対象とした集計閲覧
- 技術カテゴリ・技術マスタの参照

#### 不可能な操作

- 社員情報の登録・編集
- スキルの登録・編集・無効化
- 担当外社員の閲覧
- 社員の新規登録
- 在籍状態変更
- マスタ管理
- 組織全体の集計閲覧
- 担当社員の割り当て変更
- 権限管理

### 3.6 担当社員

サブマネージャーおよびチームリーダーには担当社員を設定する。

以下のルールとする。

- 1人のサブマネージャーに複数社員を割り当てできる
- 1人の社員に複数サブマネージャーを割り当てできる
- 1人のチームリーダーに複数社員を割り当てできる
- 1人の社員に複数チームリーダーを割り当てできる
- 同一社員にサブマネージャーとチームリーダーの両方を割り当てできる
- 担当社員の割り当て・解除は権限管理可能な管理ユーザーのみ行える
- 担当社員から外れた場合、その時点から対象社員を閲覧・操作できなくなる
- 担当変更によって社員情報・スキル情報そのものは削除されない

## 4. 管理する情報

### 4.1 社員情報

以下を管理する。

| 項目 | 必須 |
| --- | --- |
| 社員番号 | 必須 |
| 氏名 | 必須 |
| 所属部署 | 必須 |
| 職種 | 任意 |
| 在籍状態 | 必須 |

以下は初期リリースでは管理しない。

- チーム
- 役職
- 入社年月
- メールアドレス
- プロフィール画像

### 4.2 在籍状態

以下の状態を管理する。

- 在籍
- 休職
- 退職

## 5. スキル管理

### 5.1 スキルカテゴリ

初期リリースでは以下のカテゴリを扱う。

- プログラミング言語
- フレームワーク
- OS
- データベース
- ミドルウェア
- クラウドサービス
- 開発ツール
- 設計・アーキテクチャ
- セキュリティ
- インフラ・ネットワーク
- テスト・QA
- CI/CD・DevOps
- マネジメント
- 業務知識

以下は初期リリース対象外とする。

- ソフトスキル
- 資格

カテゴリは管理ユーザーが追加・変更できる。

### 5.2 技術・スキルマスタ

社員へ登録するスキルは技術・スキルマスタから選択する。

自由入力による社員スキル登録は許可しない。

必要な技術・スキルが存在しない場合、管理ユーザーがマスタへ追加してから社員へ登録する。

#### マスタのルール

- スキルは1つのカテゴリに所属する
- 技術・スキルの階層構造は持たない
- バージョン情報は管理しない
- 名称変更を可能とする
- 不要な技術・スキルは完全削除せず無効化する
- 重複した技術・スキルは統合できる

### 5.3 社員スキル

社員ごとに以下の情報を管理する。

| 項目 | 内容 |
| --- | --- |
| 技術・スキル | 技術・スキルマスタから選択 |
| 実務経験 | あり / なし |
| 経験年数 | 年 + 月 |
| スキルレベル | Level 1〜5 |
| 最終利用時期 | 年月 |
| コメント | 任意 |
| 実績・経験内容 | 任意 |

実務未経験の技術・スキルも登録可能とする。

## 6. 業務ルール

### 6.1 経験年数

経験年数には実務経験のみを含める。

以下は経験年数に含めない。

- 個人開発
- 学習
- OSS活動

経験年数は「年 + 月」で入力・表示する。

同一技術を複数案件で同時に使用していた場合、重複期間を二重に加算しない。

### 6.2 実務経験あり

実務経験が「あり」の場合、以下を必須とする。

- 経験年数1か月以上
- 最終利用時期

最終利用時期は、その技術・スキルを実務で最後に利用した年月とする。

例：

```text
PHP
実務経験：あり
経験年数：3年6か月
スキルレベル：Level 4
最終利用時期：2026/08
```

### 6.3 実務経験なし

実務経験が「なし」の場合、以下のルールとする。

- 経験年数は0年0か月とする
- 最終利用時期は設定しない
- スキルレベルは設定可能とする

例：

```text
Go
実務経験：なし
経験年数：0年0か月
スキルレベル：Level 2
最終利用時期：未設定
```

### 6.4 スキルレベル

すべてのスキルカテゴリで共通の5段階評価を使用する。

| Level | 定義 |
| --- | --- |
| Level 1 | 学習経験・基本的な知識がある |
| Level 2 | サポートがあれば業務で利用できる |
| Level 3 | 一人で業務を遂行できる |
| Level 4 | 他メンバーを支援・レビューできる |
| Level 5 | 技術選定・設計・指導ができる |

スキルレベルは上司による評価とする。

初期リリースでは自己評価は扱わない。

### 6.5 社員スキルの無効化

社員に登録されたスキルは完全削除せず、無効化して保持する。

無効化されたスキルは以下の扱いとする。

- 通常の社員スキル一覧に表示しない
- 社員検索に使用しない
- 技術別社員一覧に表示しない
- ダッシュボード集計に含めない
- 必要に応じて再度有効化できる

スキル情報の変更履歴は初期リリースでは保持しない。

### 6.6 休職社員

休職社員は原則として通常の閲覧・検索対象外とする。

- 社員検索から除外する
- スキル検索から除外する
- 技術別社員一覧から除外する
- ダッシュボード集計から除外する
- 社員情報・スキル情報自体は保持する
- 在籍状態が在籍へ戻った場合、通常の対象へ戻す

管理上必要な場合、管理ユーザーは休職社員を確認できるものとする。

### 6.7 退職社員

退職社員は通常の検索・集計対象外とする。

退職後3年間は社員情報・スキル情報を保持する。

3年経過後、自動削除は行わず、管理ユーザーが対象社員を確認したうえで削除する。

## 7. 検索・集計要件

### 7.1 社員検索

以下を検索条件とする。

- 氏名
- 在籍状態
- 技術・スキル
- 技術カテゴリ
- 経験年数
- スキルレベル
- 実務経験あり / なし

### 7.2 複数スキル検索

複数の技術・スキルを指定した検索を可能とする。

AND / ORの両方を利用可能とする。

例：

```text
PHP AND Laravel AND AWS
```

または、

```text
Go OR Rust
```

複雑なAND / OR条件の組み合わせについては詳細仕様策定時に決定する。

### 7.3 社員別スキル表示

社員詳細ではスキルをカテゴリ別に表示する。

表示項目は以下とする。

- 技術・スキル名
- カテゴリ
- 経験年数
- スキルレベル
- 実務経験あり / なし
- 最終利用時期
- コメント

実績・経験内容の表示方法については詳細仕様策定時に決定する。

### 7.4 技術・スキル別社員一覧

技術・スキルごとに、そのスキルを保有する社員を確認できるようにする。

表示項目は以下とする。

- 社員名
- 経験年数
- スキルレベル
- 実務経験あり / なし
- 最終利用時期

### 7.5 ダッシュボード

初期リリースでは技術・スキルごとの保有人数を確認できるようにする。

集計対象は「在籍」の社員のみとする。

以下は集計対象外とする。

- 休職社員
- 退職社員
- 無効化された社員スキル
- 無効化された技術・スキル

経験年数分布、スキルレベル分布、不足スキル分析などは初期リリースでは対象外とする。

## 8. 初期リリースの機能要件

### 8.1 社員管理

- 社員一覧を表示できる
- 社員詳細を表示できる
- 社員を登録できる
- 社員基本情報を編集できる
- 在籍状態を管理できる

### 8.2 スキル管理

- 社員のスキルをカテゴリ別に確認できる
- 社員へスキルを登録できる
- 社員スキルを編集できる
- 社員スキルを無効化できる
- 無効化した社員スキルを再有効化できる

### 8.3 マスタ管理

- スキルカテゴリを管理できる
- 技術・スキルマスタを管理できる
- 技術・スキルを無効化できる
- 技術・スキルの名称を変更できる
- 重複した技術・スキルを統合できる

### 8.4 検索

- 社員を検索できる
- 技術・スキルを条件として社員を検索できる
- 経験年数を条件として検索できる
- スキルレベルを条件として検索できる
- 実務経験の有無を条件として検索できる
- 複数スキルをAND / OR条件で検索できる

### 8.5 集計

- 技術・スキルごとの保有人数を確認できる

### 8.6 権限

- 利用者に権限を設定できる
- サブマネージャーに担当社員を設定できる
- チームリーダーに担当社員を設定できる
- 権限に応じて閲覧・編集可能な社員を制限できる

## 11. 本書で定義しない事項

本書では以下の技術的事項を定義しない。

- システムアーキテクチャ
- プログラミング言語
- フレームワーク
- データベース
- テーブル設計
- API設計
- URL設計
- インフラ構成
- 認証方式
- デプロイ方式
- 画面デザインの詳細

これらはMVPおよびUser Storyを確定した後、設計フェーズで検討する。

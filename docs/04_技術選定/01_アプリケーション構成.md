# アプリケーション構成

## 1. 採用構成

- [ ] モノリス
- [x] Frontend / Backend 分離

Repository については以下とする。

- [x] Frontend と Backend を1つの Repository で管理する
- [ ] Frontend と Backend を別 Repository で管理する

Frontend / BFF と Backend API は別々の Application として構成し、Source Code は1つの Git Repository で管理する。

この構成を monorepo とする。

---

## 2. 全体構成

本アプリケーションでは以下の構成を採用する。

```text
Browser
   ↓
Next.js
Frontend / BFF
   ↓
Laravel API
   ↓
PostgreSQL
```

各 Component には以下を採用する。

| 領域 | 採用技術 |
|---|---|
| Frontend / BFF | Next.js |
| Backend API | Laravel |
| Database | PostgreSQL |
| Web Authentication | Auth.js |
| Backend API Authentication | Laravel Sanctum |
| API Contract | OpenAPI |
| Development Environment | Docker |

Browser から Laravel API へ直接アクセスする構成を基本とせず、Next.js を BFF として経由する。

---

## 3. Repository 構成

Frontend と Backend は独立した Application として扱うが、1つの Git Repository で管理する。

概念上の構成は以下とする。

```text
engineer-skill-management-app/
├── frontend/
├── backend/
├── docs/
├── docker/
├── .github/
├── compose.yaml
└── README.md
```

Frontend と Backend は以下の観点では独立して管理する。

- Runtime
- Dependency
- Build
- Test
- Configuration
- Deployment

一方で以下は Repository 内で共有して管理する。

- Requirements
- User Story
- Acceptance Criteria
- OpenAPI
- Development Rules
- CI / Automation
- Project Documentation
- Local Development Environment

---

## 4. Frontend / BFF の責務

Frontend / BFF には Next.js を採用する。

Next.js は Frontend と BFF の2つの責務を持つ。

```text
Next.js
├── Frontend
└── BFF
```

Frontend として主に以下を担当する。

- 画面表示
- Routing
- ユーザー操作
- Form
- 入力状態管理
- API Response の表示
- クライアント側の入力補助
- 権限に応じた UI 表示制御

BFF として主に以下を担当する。

- Auth.js による Web Authentication
- Session 管理
- Laravel API の呼び出し
- Browser と Backend API の境界
- Web 向け Data Transformation
- Browser に公開する情報の制御

業務ルールを Next.js に実装しない。

Frontend の Validation や UI 制御だけで Security や Data Integrity を保証しない。

---

## 5. Backend API の責務

Backend API には Laravel を採用する。

Laravel は主に以下を担当する。

- API 提供
- UseCase
- Domain Logic
- Authorization
- Backend Validation
- Transaction
- Persistence
- Application Data 管理
- 権限制御

業務上重要なルールは Backend で必ず保証する。

例えば以下を含む。

- 実務未経験の場合は Level 1 のみ
- 実務経験ありの場合は経験期間1か月以上
- 実務経験ありの場合は最終利用年月必須
- 同一社員に同一 Skill を重複登録できない
- Role に応じて操作可能な社員を制限する
- Permission を管理可能な Administrator を最低1人維持する

Backend 内部では以下を採用する。

- Clean Architecture
- Domain-Driven Design
- Lightweight CQRS

詳細は Backend Architecture ドキュメントで管理する。

## 6. Database の責務

Database には PostgreSQL を採用する。

Application Data は Laravel が所有する。

```text
Laravel
   ↓
PostgreSQL
   ↓
Application Data
```

Next.js から Application Data へ直接アクセスしない。

```text
NG

Next.js
   ↓
Application Tables
```

Application Data が必要な場合は Laravel API を利用する。

```text
OK

Next.js
   ↓
Laravel API
   ↓
PostgreSQL
```

Auth.js の Session Data については Next.js / Auth.js が所有する。

Database の詳細方針は `02_データベース.md` で管理する。

## 7. API による連携

Frontend / BFF と Backend API は HTTP API を通して通信する。

```text
Browser
   ↓ HTTPS
Next.js
   ↓ HTTPS / API
Laravel
   ↓
PostgreSQL
```

Frontend / Backend 間の API Contract は OpenAPI で管理する。

OpenAPI First を採用し、API 定義を Frontend と Backend の共通契約とする。

```text
OpenAPI
├── Frontend API Client
└── Backend API Implementation
```

API の詳細は `04_API・OpenAPI.md` で管理する。

## 8. Authentication の責務

Authentication は Next.js と Laravel で責務を分離する。

```text
Browser
   ↓
Auth.js Session
   ↓
Next.js
   ↓
Laravel Sanctum
   ↓
Laravel API
```

### Browser ↔ Next.js

Auth.js が担当する。

主に以下を管理する。

- Login
- Logout
- Session
- Session Validation
- Session Lifecycle

### Next.js ↔ Laravel

Laravel Sanctum を利用する。

Laravel は Backend API への Authentication と Authorization を担当する。

Auth.js Session と Sanctum は別の責務として扱う。

認証方式の詳細は `03_認証方式.md` で管理する。

## 9. monorepo を採用する理由

### メリット

- Frontend と Backend を1つの Repository で管理できる
- Issue や Pull Request をまとめて管理できる
- 1つの機能変更を Frontend / Backend 横断でレビューしやすい
- API 変更と Frontend 変更を同じ Pull Request で扱える
- OpenAPI を共有しやすい
- Documentation をまとめて管理できる
- CI / Automation を一元管理しやすい
- Local Development Environment を統一しやすい
- MVP 規模では Repository 管理がシンプルになる

### デメリット

- Repository が将来的に大きくなる可能性がある
- Frontend と Backend で異なる Toolchain を管理する必要がある
- CI で変更対象外の Application を不要に実行しない工夫が必要になる
- Directory と責務境界を明確に保つ必要がある

現時点ではメリットがデメリットを上回るため monorepo を採用する。

---

## 10. 独立性

Frontend / BFF と Backend API は、それぞれ独立した Application として扱う。

```text
Monorepo
├── Next.js Application
└── Laravel Application
```

一方の内部実装に他方を直接依存させない。

両 Application 間の境界は API Contract とする。

```text
Next.js
   ↓
OpenAPI Contract
   ↓
Laravel
```

---

## 11. MVP での方針

MVP でも Frontend / Backend 分離構成を採用する。

ただし、必要以上に複雑な Distributed Architecture にはしない。

MVP では以下を採用しない。

- Microservices
- Backend の複数 Service 分割
- Event-Driven Architecture
- Event Sourcing
- Full CQRS
- API Gateway
- 複雑な Service 間通信
- Database per Service

Backend API は1つの Laravel Application とする。

```text
Backend
└── Laravel Application
```

Application 内部の責務分離には Clean Architecture / DDD / Lightweight CQRS を利用するが、Infrastructure を物理的に分散させない。

---

## 12. 設計原則

本構成では以下を基本原則とする。

### 業務ルールは Backend で保証する

Frontend の UI 制御や Client Validation は User Experience 改善を目的とする。

Security、Authorization、Domain Invariant、Data Integrity を Frontend のみに依存させない。

### Application Data は Laravel が所有する

Next.js から Application Table へ直接アクセスしない。

### Web 固有の責務は Next.js に置く

UI、Web Session、BFF の責務を Next.js に配置する。

### API を境界とする

Frontend / BFF と Backend の接続は OpenAPI で定義された API Contract を基準とする。

### Simple First

将来的な拡張を考慮しつつ、MVP では必要以上に Infrastructure を複雑化しない。

### Next.js Only

```text

   ↓
Next.js
   ↓
PostgreSQL
```

Next.js に Domain Logic と Application Data Access を集約する構成は採用しない。

---

### Browser → Laravel Direct Access

```text
Browser
   ↓
Laravel API
```

Browser から Laravel API を直接利用することを基本構成としない。

Next.js BFF を経由する。

---

### Laravel SSR

Laravel に UI / SSR の責務を持たせない。

Web UI は Next.js が担当する。

---

### Repository 分割

Frontend と Backend を別々の Git Repository には分割しない。

---

### Microservices

MVP では採用しない。

単一 Laravel Backend を基本とする。

## 15. 決定事項

### Application 構成

**Frontend / Backend 分離構成を採用する。**

```text
Browser
   ↓
Next.js
Frontend / BFF
   ↓
Laravel API
   ↓
PostgreSQL
```

### Repository 構成

**monorepo を採用する。**

```text
Monorepo
├── Frontend / BFF
│   └── Next.js
│
└── Backend API
    └── Laravel
```

### 責務

- Next.js は Frontend / BFF を担当する
- Auth.js は Web Authentication / Session を担当する
- Laravel は UseCase / Domain Logic / Authorization を担当する
- Laravel Sanctum は Next.js → Laravel API 間の Authentication に利用する
- PostgreSQL は Persistence を担当する
- Application Data は Laravel が所有する
- Frontend / Backend 間の Contract は OpenAPI で管理する

### MVP 方針

- Frontend と Backend は独立 Application とする
- Source Code は1つの Git Repository で管理する
- Browser → Next.js → Laravel を基本経路とする
- Backend は単一 Laravel Application とする
- Microservices は採用しない
- 業務ルールと権限制御は Backend で保証する

この構成を今後の設計・実装における基本方針とする。

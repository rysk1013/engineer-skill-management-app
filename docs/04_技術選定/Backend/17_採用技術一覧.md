# Backend 採用技術一覧

## 1. 目的

本ドキュメントでは、Engineer Skill Management App のBackendについて、`01`〜`16`で決定した技術・Library・Architecture・運用方針を一覧化する。

各Documentでは、

```text
Why
How
Rules
```

を詳細に定義している。

本ドキュメントでは主に、

```text
What
```

を確認できるようにする。

目的：

- 採用技術を一覧で確認する
- 不採用技術を明確にする
- 条件付き採用を整理する
- 将来候補を整理する
- 詳細Documentへの入口とする
- Backend全体の技術選定に矛盾がないか確認する

---

# 2. 採用Status

本ドキュメントでは以下のStatusを使用する。

| Status | 意味 |
|---|---|
| 採用 | MVPから正式利用する |
| 条件付き採用 | 必要条件を満たした場合に利用する |
| 将来候補 | 現時点では利用しないが将来的に再検討する |
| 不採用 | 現在のArchitecture / MVPでは利用しない |

# 59. Package追加原則


# 66. 最終方針

Backend技術選定では、

> 必要なBoundaryを明確にし、標準機能を優先し、外部Libraryへの依存を必要最小限に保つ

ことを基本方針とする。

Technologyを増やすことではなく、

```text
Type Safety
Maintainability
Security
Testability
Observability
Reproducibility
Developer Experience
```

を高めるために技術を選定する。

最終的なBackend構成は、

```text
Laravel
+
PostgreSQL
+
Clean Architecture
+
DDD
+
Lightweight CQRS
+
OpenAPI First
+
Strong Automated Testing
+
Static Analysis
+
Observability
+
Security Automation
+
GitHub Actions
```

を中心とする。

学習目的として一定のArchitecture Designを取り入れつつも、

```text
Full CQRS
Event Sourcing
Microservices
Excessive Framework
Excessive Abstraction
```

のような、現時点のRequirementに対して不要な複雑性は導入しない。

これをEngineer Skill Management App Backendの技術選定決定版とする。

# フロントエンド技術選定

## 1. 目的

本ドキュメントでは、Engineer Skill Management AppのFrontendおよびBFFで利用する技術・Libraryの選定方針と全体像を管理する。

具体的な技術・Libraryの比較、採用理由、利用範囲については `Frontend/` 配下の各ドキュメントで管理する。

Frontendのレイヤー構成、Server / Client境界、データ取得、状態管理などの設計についてはFrontend Architectureで管理し、本ドキュメントでは詳細なArchitecture設計を扱わない。

---

## 2. Frontend構成

FrontendにはNext.jsを採用し、Frontendアプリケーション兼BFFとして利用する。

基本構成は以下とする。

    Browser
       |
       v
    Next.js
    Frontend + BFF
       |
       v
    Backend API
       |
       v
    PostgreSQL

BrowserからBackend APIを直接利用することは原則として行わない。

Next.jsからPostgreSQLへ直接アクセスせず、業務データへのアクセスはBackend APIを経由する。

---

## 3. 基本技術

Frontendの基本技術として以下を採用する。

| 分類 | 採用技術 |
| --- | --- |
| Runtime | Node.js 24 LTS |
| Language | TypeScript |
| UI | React 19 |
| Framework | Next.js |
| Router | App Router |
| Package Manager | pnpm |
| BFF | Next.js |

具体的なPatch Versionは本ドキュメントでは固定しない。

実際に利用するバージョンは `package.json`、Lockfile、Dockerfileなどのリポジトリ内の設定で管理する。

---

## 4. 基本方針

Frontendの技術・Library選定では以下を基本方針とする。

- Next.js / Reactの標準機能を優先する
- TypeScriptを前提とする
- OpenAPIをBackend APIとの契約のSource of Truthとする
- Server Firstを基本とする
- 状態の種類ごとに管理方法を分ける
- Library間の責務を重複させない
- Headless / ComposableなLibraryを優先する
- 型安全性を重視する
- 不要なLibraryを導入しない
- MVPで必要なものを優先する
- Architectureと技術選定を分離する

詳細は `Frontend/01_基本方針.md` で管理する。

## 8. 技術選定の管理方針

各技術・Libraryについて、必要に応じて以下を記録する。

1. 候補
2. 採用する技術・Library
3. 採用理由
4. 利用範囲
5. 採用しない候補とその理由

比較する意味が小さい基本技術については、不要な比較を行わず採用方針のみ記載する。

---

## 9. MVPでの方針

MVPでは必要な技術・Libraryのみを導入する。

将来的に必要になる可能性だけを理由としてLibraryを導入しない。

Next.jsまたはReactの標準機能で十分に実現できる場合は、追加Libraryを導入しないことを基本とする。

必要性が明確になった時点で追加できる構成を維持する。

---

## 10. 決定事項

Frontendは以下を基本構成とする。

    Node.js
       |
       v
    Next.js + React + TypeScript
       |
       +-- Frontend
       |
       +-- BFF
       |
       v
    Backend API

Package Managerにはpnpmを採用する。

Frontend Architectureと技術選定を分離し、

    Frontend Architecture
        ↓
    どう設計するか

    Frontend技術選定
        ↓
    何を使うか

として管理する。

具体的な技術・Libraryの選定結果は `Frontend/` 配下で管理し、本ドキュメントをFrontend技術選定全体のサマリー兼入口とする。

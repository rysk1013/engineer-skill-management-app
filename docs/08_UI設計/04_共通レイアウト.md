# 共通レイアウト

## 1. 目的

本ドキュメントは、Engineer Skill Management App の認証後画面で共通して利用するレイアウトを定義する。

対象は以下とする。

- App Shell
- Header
- Sidebar
- Main Content
- Breadcrumb
- Page Header
- Page Content
- Navigation
- Responsive時のレイアウト変化
- 権限によるNavigation表示制御

本ドキュメントで定義した共通レイアウトを、各画面のUI設計およびFrontend実装の基準とする。

---

## 2. 基本方針

共通レイアウトは以下を基本とする。

```text
+----------------------------------------------------------+
| Header                                                   |
+------------------+---------------------------------------+
|                  |                                       |
| Sidebar          | Main Content                          |
|                  |                                       |
|                  |                                       |
|                  |                                       |
+------------------+---------------------------------------+
```

認証後画面は原則として同一のApp Shellを利用する。

各画面が独自にHeader・Sidebar・Main Content構造を持つことは避ける。

---

## 3. App Shell

App Shellは、認証後画面の共通骨格を提供する。

基本構造は以下とする。

```text
App Shell
├── Header
├── Sidebar
└── Main Content
    ├── Breadcrumb
    ├── Page Header
    └── Page Content
```

App Shellは以下の責務を持つ。

- Application全体の共通Navigationを提供する
- 現在位置を把握できるようにする
- ユーザー情報・共通操作への入口を提供する
- 各画面固有Contentの表示領域を提供する
- Responsive時のNavigation切り替えを担う

---

## 4. Header

### 4.1 役割

HeaderはApplication全体で共通する情報・操作を配置する。

主な役割は以下とする。

- Application識別
- Mobile / Tablet時のNavigation操作
- ユーザー情報表示
- ユーザー共通操作への入口

---

### 4.2 基本構成

Desktopでは以下を基本とする。

```text
+----------------------------------------------------------+
| Application Name                         User Menu        |
+----------------------------------------------------------+
```

Tablet / Mobileでは必要に応じてNavigation Toggleを追加する。

```text
+----------------------------------------------------------+
| Menu | Application Name                  User Menu        |
+----------------------------------------------------------+
```

---

### 4.3 Application Name

HeaderにはApplication名またはApplicationを識別できる表示を配置する。

Application Nameを選択した場合は、Dashboardへ遷移できる構成を基本とする。

```text
Application Name
      |
      v
      /
```

---

### 4.4 User Menu

Header右側にUser Menuを配置することを基本とする。

主な表示候補は以下とする。

- ログインユーザー名
- Role
- Logout

MVPで不要なAccount Setting等は、必要性が確定するまで追加しない。

User Menuの具体的なComponentは `06_共通コンポーネント.md` で定義する。

---

## 5. Sidebar

### 5.1 役割

Sidebarは認証後Applicationの主要Navigationを提供する。

主要機能間の移動はSidebarを基本とする。

---

### 5.2 Navigation構造

基本Navigationは以下とする。

```text
Dashboard

Employee
└── 社員一覧

Skill
├── スキル一覧
└── スキルカテゴリ一覧

Administration
└── アクセス制御
```

Navigation Labelの最終的な日本語 / 英語表記はUI詳細設計で統一する。

---

### 5.3 Dashboard

DashboardへのNavigationを配置する。

```text
Dashboard
    ↓
    /
```

---

### 5.4 Employee

社員管理機能への入口として社員一覧を配置する。

```text
Employee
└── 社員一覧
       ↓
   /employees
```

以下のRouteでは社員NavigationをActiveとして扱う。

```text
/employees
/employees/create
/employees/[employeeId]
/employees/[employeeId]/edit
/employees/[employeeId]/skills
```

---

### 5.5 Skill

Skill配下には以下を配置する。

```text
Skill
├── スキル一覧
│      ↓
│   /skills
│
└── スキルカテゴリ一覧
       ↓
   /skill-categories
```

以下のRouteではスキル一覧をActiveとして扱う。

```text
/skills
/skills/create
/skills/[skillId]/edit
```

以下のRouteではスキルカテゴリ一覧をActiveとして扱う。

```text
/skill-categories
/skill-categories/create
/skill-categories/[skillCategoryId]/edit
```

---

### 5.6 Administration

Administrationには管理機能を配置する。

MVPでは以下を対象とする。

```text
Administration
└── アクセス制御
       ↓
   /access-control
```

Administration自体または配下項目は、権限に応じて表示制御する。

---

## 6. Navigationの権限制御

NavigationはRole / Permissionに応じて表示を制御する。

Frontend上のNavigation非表示はUI制御であり、認可そのものとはしない。

最終的な認可はBackendを正とする。

### 6.1 基本方針

ユーザーが利用できない機能はNavigationに表示しないことを基本とする。

例:

```text
権限管理可能
    ↓
Administration
└── Access Control を表示
```

```text
権限管理不可
    ↓
Administration
└── Access Control を表示しない
```

---

### 6.2 Groupの表示

Navigation Group配下に表示可能な項目が1件もない場合は、Group自体を表示しないことを基本とする。

例:

```text
Administration
└── 表示可能項目なし
```

の場合、

```text
Administration
```

自体を表示しない。

---

## 7. NavigationのActive表示

現在表示している機能をSidebar上で識別できるようにする。

Active状態はRoute単位ではなく、利用者が認識する機能単位でまとめる。

例:

```text
/employees
/employees/create
/employees/[employeeId]
/employees/[employeeId]/edit
/employees/[employeeId]/skills
```

はいずれもEmployee配下として扱う。

ただし、同一Groupに複数Navigation Itemがある場合は、可能な限り具体的な項目をActiveとする。

例:

```text
/skills/*
    ↓
スキル一覧

/skill-categories/*
    ↓
スキルカテゴリ一覧
```

Active状態は色だけで表現せず、背景・文字・Indicator等を組み合わせて識別可能にする。

---

## 8. Main Content

### 8.1 役割

Main Contentは各画面固有のContentを表示する領域とする。

基本構造は以下とする。

```text
Main Content
├── Breadcrumb
├── Page Header
└── Page Content
```

---

### 8.2 Content幅

画面ごとに無制限に異なる最大幅を定義しない。

基本的なContent幅・左右Paddingは共通ルールとして管理する。

Table等、横幅を必要とする画面では利用可能幅を広く使用できる構成とする。

Formや詳細画面については、可読性のため必要以上に横幅を広げない。

具体的なWidth TokenはDesign Systemで定義する。

---

### 8.3 Vertical Spacing

Breadcrumb、Page Header、Page Content間のSpacingは共通化する。

画面ごとに独自のMarginを積み重ねて調整することは避ける。

---

## 9. Breadcrumb

### 9.1 役割

Breadcrumbは、現在位置と上位画面との関係を利用者が把握できるようにする。

認証後の詳細・登録・編集画面ではBreadcrumbを表示することを基本とする。

---

### 9.2 例

社員一覧:

```text
Employees
```

社員詳細:

```text
Employees > 社員名
```

社員登録:

```text
Employees > 登録
```

社員編集:

```text
Employees > 社員名 > 編集
```

社員スキル編集:

```text
Employees > 社員名 > スキル編集
```

スキル登録:

```text
Skills > 登録
```

アクセス制御編集:

```text
Access Control > ユーザー名 > 編集
```

---

### 9.3 Dashboard

DashboardではBreadcrumbを省略可能とする。

```text
/
```

のみを表示している状態で、

```text
Dashboard
```

というBreadcrumbを追加してもNavigation上の情報量が増えないため、個別設計で不要と判断できる。

---

### 9.4 Breadcrumbのリンク

現在ページ以外のBreadcrumb Itemは、遷移可能な場合はLinkとする。

現在ページはLinkにしないことを基本とする。

---

## 10. Page Header

### 10.1 基本構造

各主要画面にはPage Headerを配置する。

基本構造は以下とする。

```text
Page Header
├── Title
├── Description
└── Action
```

Desktopでは以下のような構成を基本とする。

```text
+----------------------------------------------------------+
| Title                                    Primary Action  |
| Description                                              |
+----------------------------------------------------------+
```

---

### 10.2 Title

画面の目的が分かる短い名称を表示する。

例:

- 社員一覧
- 社員詳細
- 社員登録
- スキル一覧
- スキルカテゴリ一覧
- アクセス制御

同じ機能で画面ごとに大きく異なる用語を使わない。

---

### 10.3 Description

補足説明が必要な画面のみDescriptionを表示する。

すべての画面で形式的にDescriptionを表示する必要はない。

---

### 10.4 Primary Action

Page全体で最も主要な操作がある場合は、Page Header右側へPrimary Actionを配置することを基本とする。

例:

```text
社員一覧
    ↓
社員登録
```

```text
スキル一覧
    ↓
スキル登録
```

Primary Actionがない画面では空の領域を維持する必要はない。

---

### 10.5 Secondary Action

Secondary ActionをPage Headerへ大量に並べない。

複数Actionがある場合は、

- Main Content内へ配置
- Dropdown Menuへまとめる
- Detail Section単位で配置

など、Actionの意味に応じて整理する。

---

## 11. Page Content

Page Contentは画面固有のUIを配置する。

主なContent例:

- Table
- Search / Filter
- Detail
- Form
- Card
- Empty State
- Error State

共通レイアウト側では画面固有のContent構造を固定しない。

個別画面設計で定義する。

---

## 12. 一覧画面レイアウト

一覧画面は以下の構造を基本とする。

```text
Breadcrumb

Page Header
├── Title
└── Create Action

Search / Filter

Table

Pagination
```

例:

```text
Employees

社員一覧                           社員登録

[ Search ] [ Filter ]

+--------------------------------------------------+
| Table                                            |
+--------------------------------------------------+

                    Pagination
```

Search / Filterが不要な画面では省略可能とする。

---

## 13. 詳細画面レイアウト

詳細画面は以下を基本とする。

```text
Breadcrumb

Page Header
├── Title
└── Edit Action

Detail Content

Related Content
```

社員詳細では例として以下を想定する。

```text
Employees > 社員名

社員名                              編集

基本情報

保有スキル                          スキル編集
```

複数の情報Groupを持つ場合は、Section単位で整理する。

---

## 14. Form画面レイアウト

登録・編集画面は以下を基本とする。

```text
Breadcrumb

Page Header
└── Title

Form
├── Field Group
├── Field Group
└── Action
    ├── Primary
    └── Cancel
```

FormのActionは、画面間で位置を統一する。

基本的に以下を想定する。

```text
[ Cancel ] [ Save ]
```

またはUI全体の方向性に応じて、

```text
[ Save ] [ Cancel ]
```

のどちらかへ統一する。

最終順序はDesign System / 個別画面設計で決定し、画面ごとに変えない。

---

## 15. Desktopレイアウト

DesktopではSidebarを常時表示することを基本とする。

```text
+----------------------------------------------------------+
| Header                                                   |
+------------------+---------------------------------------+
| Sidebar          | Main Content                          |
|                  |                                       |
| Navigation       | Breadcrumb                            |
|                  | Page Header                           |
|                  | Page Content                          |
+------------------+---------------------------------------+
```

Desktopでは以下を優先する。

- Navigationの常時視認性
- Tableの一覧性
- Content領域の確保
- Primary Actionの発見しやすさ

---

## 16. Tabletレイアウト

Tabletでは画面幅に応じてSidebarの表示方式を切り替える。

候補は以下とする。

- Compact Sidebar
- Collapsible Sidebar
- Overlay Sidebar

最終的な方式はResponsive設計で決定する。

Main Contentの構造はDesktopと可能な限り維持する。

---

## 17. Mobileレイアウト

MobileではSidebarを常時表示しない。

HeaderからNavigationを開く方式を基本とする。

```text
+----------------------------------+
| Menu | Application | User       |
+----------------------------------+
|                                  |
| Breadcrumb                       |
|                                  |
| Page Header                      |
|                                  |
| Page Content                     |
|                                  |
+----------------------------------+
```

NavigationはOverlayまたはDrawer形式を基本候補とする。

MobileでNavigationを開いている場合は、Main Contentとの操作対象を明確に分離する。

---

## 18. Mobile Page Header

MobileではPage HeaderのTitleとActionを横並びにできない場合がある。

その場合は縦方向へ配置する。

```text
Title
Description

[ Primary Action ]
```

Primary Actionを画面外へ押し出さず、利用者が発見可能な位置を維持する。

---

## 19. Mobile Table

MobileではDesktopと同じTableをそのまま縮小表示しない。

以下から画面ごとに適切な方式を選択する。

- 横スクロール
- 表示Column削減
- Mobile向け情報配置
- Card形式への変更

ただし、同一データについてDesktopとMobileで意味が異なる表示にはしない。

具体的な方式は個別画面設計およびResponsive設計で決定する。

---

## 20. Loading時のレイアウト

LoadingによってPage全体の構造が大きく変化しないことを基本とする。

可能な限り、

```text
Breadcrumb
Page Header
Page Content Loading
```

の構造を維持する。

Page全体を単一Spinnerのみへ置き換えることは、必要な場合を除いて避ける。

---

## 21. Error / Empty時のレイアウト

Error / Empty状態でも、ユーザーが現在どの画面にいるか把握できる状態を維持する。

原則として、

```text
Breadcrumb
Page Header
Error / Empty Content
```

の構造を維持する。

ErrorやEmptyだけを画面中央へ表示し、Application Navigationを失わせることは避ける。

---

## 22. Access Denied / Not Found

Access DeniedとNot Foundは通常の業務画面とはContent構造が異なる。

ただし認証済み状態の場合は、可能な範囲でApplication内へ戻る導線を提供する。

### Access Denied

```text
Access Denied

この画面へアクセスする権限がありません。

[ Dashboardへ戻る ]
```

### Not Found

```text
Not Found

ページまたは対象データが見つかりません。

[ Dashboardへ戻る ]
```

認証済みNot FoundでApp Shellを維持するかどうかは、Next.jsのRouting構成と合わせて実装時に判断する。

---

## 23. shadcn/uiとの関係

共通レイアウトはshadcn/uiを基本UI Componentとして利用する前提で設計する。

利用候補は以下とする。

- Breadcrumb
- Button
- Dropdown Menu
- Sheet / Drawer相当
- Separator
- Tooltip

ただし、この段階では導入Componentを確定しない。

実際に採用するshadcn/ui Componentは `06_共通コンポーネント.md` で決定する。

Application固有のApp Shell、Page Header、Sidebar等については、shadcn/ui Componentを組み合わせたApplication共通Componentとして設計する。

---

## 24. Icon

Navigationや共通操作のIconにはLucide / `lucide-react` を使用する前提とする。

IconはTextの補助として利用し、意味をIconだけへ依存させない。

例:

```text
[Icon] 社員一覧
[Icon] スキル
[Icon] アクセス制御
```

NavigationでIconを使用するかどうかはDesign Systemで視覚方針を決定する。

---

## 25. Accessibility

共通レイアウトでは以下を考慮する。

- HeaderにはSemanticな `header` を利用する
- Sidebar Navigationには `nav` を利用する
- Main Contentには `main` を利用する
- NavigationをKeyboardで操作可能にする
- Active Navigationを色だけで表現しない
- Mobile Navigation開閉ButtonにAccessible Nameを提供する
- Mobile Navigation開閉時のFocus Managementを考慮する
- BreadcrumbをSemanticに表現する
- Focus Ringを理由なく削除しない

---

## 26. 共通レイアウトで定義しないもの

以下は本ドキュメントでは詳細定義しない。

- Colorの具体値
- Typographyの具体値
- Spacingの具体値
- Sidebarの具体的な幅
- Headerの具体的な高さ
- Breakpointの具体値
- Button Variant
- Table Styling
- Form Control Styling

これらは `05_デザインシステム.md` および `06_共通コンポーネント.md` で定義する。

---

## 27. レイアウト構造まとめ

認証後Desktopの基本構造は以下とする。

```text
App Shell
│
├── Header
│   ├── Application
│   └── User Menu
│
├── Sidebar
│   ├── Dashboard
│   ├── Employee
│   ├── Skill
│   │   ├── スキル一覧
│   │   └── スキルカテゴリ一覧
│   └── Administration
│       └── Access Control
│
└── Main
    ├── Breadcrumb
    ├── Page Header
    │   ├── Title
    │   ├── Description
    │   └── Primary Action
    └── Page Content
```

Mobileでは以下を基本とする。

```text
App Shell
│
├── Header
│   ├── Navigation Toggle
│   ├── Application
│   └── User Menu
│
├── Mobile Navigation
│   └── 必要時のみ表示
│
└── Main
    ├── Breadcrumb
    ├── Page Header
    └── Page Content
```

本ドキュメントで定義した共通レイアウトを基準として、後続ドキュメントで以下を詳細化する。

```text
04_共通レイアウト
    ↓
05_デザインシステム
    ↓
06_共通コンポーネント
    ↓
07_画面設計
    ↓

    ↓

```

後続設計によって共通レイアウトの変更が必要になった場合は、個別画面だけで例外対応せず、本ドキュメントへ反映する。

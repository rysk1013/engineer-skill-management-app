# 画面遷移

## 1. 目的

本ドキュメントは、Engineer Skill Management App のMVPにおける画面間の遷移およびDialog等の主要UI状態変化を定義する。

`02_画面一覧.md` で定義した画面・主要UIを基準として、以下を整理する。

- 認証前後の遷移
- 主要Navigationからの遷移
- Featureごとの画面遷移
- Dialogの起点
- Routeを持たない主要Action
- 登録・更新成功後の遷移・表示更新
- キャンセル時の遷移・状態維持
- Access Denied / Not Foundへの遷移

本ドキュメントでは遷移関係を定義し、画面内部のLayout・Component構造・Error表示方法等は他のUI設計ドキュメントへ委ねる。

---

# 2. 基本方針

## 2.1 Frontend Route

Frontend RouteはNext.js App Routerで管理する。

本ドキュメントで扱うRouteは、ユーザーがブラウザ上でアクセスするFrontend Routeとする。

Backend API Routeとは分離して扱う。

---

## 2.2 独立画面への遷移

独立画面へ移動する操作ではFrontend Routeが変更される。

例:

```text
/employees
    ↓
/employees/[employeeId]
```

```text
/employees/[employeeId]
    ↓
/employees/[employeeId]/skills
```

```text
/access-control
    ↓
/access-control/[userId]/edit
```

---

## 2.3 Dialog

Dialogは独立Routeを持たないUI状態として扱う。

```text
Page
  |
  | Dialogを開く
  v
Page + Dialog
```

Dialogを開閉しても、原則として現在のFrontend Routeは変更しない。

具体的なDialog Layout・Component設計は以下を参照する。

- `04_共通レイアウト.md`
- `06_共通コンポーネント.md`

---

## 2.4 Dialog採用対象

MVPでは以下の登録・編集操作をDialogとして扱う。

```text
Employee
├── 社員登録
└── 社員編集

Skill
├── スキル登録
└── スキル編集

Skill Category
├── スキルカテゴリ登録
└── スキルカテゴリ編集
```

以下は独立画面として扱う。

```text
Employee Skill
└── 社員スキル編集

Access Control
└── ユーザー権限編集
```

---

## 2.5 Routeを持たない主要Action

MVPでは、独立画面または登録・編集Dialogとは別に、起点画面のContextを維持したまま実行するActionを扱う。

主な対象:

```text
Employee
└── 退職

Skill
└── 無効化

Employee Skill
└── 削除
```

これらのActionで確認UIを利用しても、原則としてFrontend Routeは変更しない。

---

## 2.6 キャンセル

独立した登録・編集画面では、キャンセル時に起点となる一覧・詳細画面へ戻ることを基本とする。

Dialogでは、キャンセル時にDialogを閉じて起点画面を維持する。

Routeを持たないActionの確認UIでは、キャンセル時に確認UIを閉じて起点画面を維持する。

---

## 2.7 権限制御

画面または操作を利用できないユーザーには、対象Actionを表示しないことを基本とする。

URL直接アクセス等によって権限のない独立画面へアクセスした場合はAccess Deniedとして扱う。

Frontend上の表示制御のみを認可として扱わず、最終的な認可はBackendを正とする。

---

# 3. 全体遷移

MVP全体の主要な画面遷移は以下とする。

```text

  |
  v
/login
  |
  | Login成功
  v
/
Dashboard
  |
  +-----------------------+--------------------------+
  |                       |                          |
  v                       v                          v
/employees             /skills             /skill-categories
Employee               Skill               Skill Category

/
|
└── /access-control
    Access Control
    ※権限がある場合のみ
```

各Feature内の詳細な遷移は後述する。

# 4. 認証遷移

## 4.1 未認証ユーザー

未認証ユーザーが認証必須Routeへアクセスした場合はログイン画面へ遷移する。

```text
認証必須Route
      |
      | 未認証
      v
   /login
```

---

## 4.2 ログイン成功

ログイン成功後はDashboardへ遷移する。

```text
/login
   |
   | Login成功
   v
   /
```

---

## 4.3 ログイン失敗

ログイン失敗時はRouteを変更しない。

```text
/login
   |
   | Login失敗
   v
/login
```

Error表示の詳細はUI状態設計で定義する。

---

## 4.4 認証済みユーザーのログイン画面アクセス

認証済みユーザーが `/login` へアクセスした場合はDashboardへ遷移する。

```text
/login
   |
   | 認証済み
   v
   /
```

---

## 4.5 ログアウト

ログアウト成功後はログイン画面へ遷移する。

```text
認証済み画面
      |
      | Logout
      v
   /login
```

---

# 6. Employee

## 6.1 基本遷移

```text
/employees
社員一覧
  |
  +--> 社員登録Dialog
  |
  └--> /employees/[employeeId]
       社員詳細
         |
         +--> 社員編集Dialog
         |
         +--> 退職処理UI
         |
         └--> /employees/[employeeId]/skills
              社員スキル編集
```

退職処理UIは独立Frontend Routeを持たず、社員詳細のContextを維持したまま退職日入力・確認・実行を行う。

---

## 6.2 社員一覧 → 社員登録Dialog

社員登録権限を持つユーザーは、社員一覧から社員登録Dialogを開く。

```text
/employees
    |
    | 社員登録
    v
社員登録Dialog
```

Routeは `/employees` のままとする。

---

## 6.3 社員登録成功

社員登録成功後はDialogを閉じ、作成された社員の詳細画面へ遷移する。

```text
/employees
    |
    | 社員登録Dialog
    | 登録成功
    v
/employees/[employeeId]
```

---

## 6.4 社員登録キャンセル

キャンセル時はDialogを閉じ、社員一覧を維持する。

```text
/employees
    |
    | 社員登録Dialog
    | Cancel
    v
/employees
```

Route変更は発生しない。

---

## 6.5 社員一覧 → 社員詳細

対象社員を選択すると社員詳細へ遷移する。

```text

    |

/employees/[employeeId]
```

## 6.8 社員編集キャンセル

キャンセル時はDialogを閉じ、社員詳細を維持する。

```text

        |
        | 社員編集Dialog
        | Cancel
        v
/employees/[employeeId]
```

---

## 6.9 社員詳細 → 退職処理

退職処理を実行可能なユーザーは、社員詳細から退職処理を開始する。

MVPで退職処理を実行可能なRoleは既存Employee API仕様を正とする。

```text
/employees/[employeeId]
        |
        | 退職
        v
退職処理UI
        |
        | 退職日入力・確認
        v
退職実行
```

退職処理UIは独立Frontend Routeを持たず、Routeは `/employees/[employeeId]` のままとする。

退職は通常の社員情報編集とは分離し、既存Employee API仕様で定義された専用のDomain Operationとして扱う。

退職成功後は社員詳細の表示内容を最新状態へ更新し、退職済みであることを表示する。

```text

        | 退職処理
        | 成功
        v
/employees/[employeeId]
```

Route変更は発生しない。

---

## 6.11 退職キャンセル

退職処理をキャンセルした場合は、退職処理UIを閉じて社員詳細を維持する。

```text
        | 退職処理

        v
/employees/[employeeId]
```

Route変更は発生しない。

# 10. Access Denied

## 10.1 権限のない独立画面へのアクセス

権限のない独立Routeへ直接アクセスした場合はAccess Deniedへ遷移する。

```text
権限のないRoute
       |
       v
/forbidden
```

---

## 10.2 権限のないAction

画面自体は閲覧可能だが特定操作の権限がない場合は、対象Actionを表示しないことを基本とする。

例:

```text
一覧閲覧可能
登録権限なし
    ↓
登録Actionを表示しない
```

Dialogは起動Action自体を表示しないことを基本とする。

Routeを持たない主要Actionについても、実行権限がない場合は起動Actionを表示しないことを基本とする。

---

# 11. Not Found

## 11.1 存在しないRoute

存在しないFrontend Routeへアクセスした場合はNext.jsのNot Found処理を利用する。

```text
存在しないRoute
      |
      v
Not Found
```

---

## 11.2 存在しないResource

Route自体は有効でも対象Resourceが存在しない場合はNot Foundとして扱う。

例:

```text
/employees/[存在しないemployeeId]
             |
             v
          Not Found
```

対象例:

- Employee
- User

一覧上のDialogから編集対象を取得するSkill / Skill Categoryについて、対象Resourceが操作時点で存在しなくなった場合の扱いはUI状態設計・API共通仕様に従う。

---

# 12. Validation Error

登録・更新時にValidation Errorが発生した場合は、原則として現在の画面またはDialogを維持する。

独立画面:

```text
編集画面
  |
  | Validation Error
  v
同一画面
```

Dialog:

```text
Dialog
  |
  | Validation Error
  v
同一Dialog
```

Error表示方法・Focus・Message等の詳細は `08_UI状態設計.md` で定義する。

---

# 13. API Error

登録・更新・Routeを持たない主要Actionで通常のAPI Errorが発生した場合は、原則として現在のContextを維持する。

```text
現在Context
    |
    | API Error
    v
現在Contextを維持
```

以下のように別状態として扱うべきErrorは、それぞれ対応する遷移を行う。

- 未認証
- Access Denied
- Not Found

具体的なError表示・Retry UIは `08_UI状態設計.md` で定義する。

# 14. Breadcrumbとの関係

Breadcrumbは現在表示している独立画面の階層を表す。

例:

```text
社員一覧
Employees
```

```text
社員詳細
Employees > 社員名
```

```text
社員スキル編集
Employees > 社員名 > スキル編集
```

```text
スキル一覧
Skills
```

```text
スキルカテゴリ一覧
Skill Categories
```

```text
ユーザー権限編集
Access Control > ユーザー名
```

Dialogは独立Routeを持たないため、新しいBreadcrumb階層を追加しない。

Routeを持たない主要ActionについてもBreadcrumbを変更しない。

DialogまたはRouteを持たないActionで実行中の操作は、Dialog Title・確認UI等で表現する。

具体的なBreadcrumb Layoutは `04_共通レイアウト.md` で定義する。

# 15. Navigationとの関係

Sidebar等の主要Navigationでは、現在表示しているFeatureを識別可能にする。

Employeeでは以下をEmployee Navigationの対象とする。

```text
/employees
/employees/[employeeId]
/employees/[employeeId]/skills
```

Skillでは以下をSkill Navigationの対象とする。

```text
/skills
```

Skill Categoryでは以下をSkill Category Navigationの対象とする。

```text
/skill-categories
```

Access Controlでは以下をAdministration / Access Control Navigationの対象とする。

```text
/access-control
/access-control/[userId]/edit
```

Dialog表示中およびRouteを持たないAction実行中も、元画面のNavigation Active Stateを維持する。

---

# 16. Browser Back

独立画面間の遷移では、Browser Backによる通常のNavigationを阻害しないことを基本とする。

Dialogは原則としてRouteを変更しないため、Browser BackをDialog Close操作として扱うことをMVPの必須要件としない。

Routeを持たない主要Actionの確認UIについても、Browser BackをClose操作として扱うことをMVPの必須要件としない。

未保存変更の扱いは個別画面設計およびUI状態設計で判断する。

# 18. 主要UI状態まとめ

MVPでの主要なUI状態遷移は以下とする。

```text
Employee
├── 社員登録Dialog
├── 社員編集Dialog
├── 退職処理UI → Routeを持たないAction
└── 社員スキル編集 → 独立画面

Skill
├── スキル登録Dialog
├── スキル編集Dialog
└── 無効化確認UI → Routeを持たないAction

Skill Category
├── スキルカテゴリ登録Dialog
└── スキルカテゴリ編集Dialog

Access Control
└── ユーザー権限編集 → 独立画面
```

DialogおよびRouteを持たないAction UIは元画面のContextを維持し、独立画面はFrontend Routeによって作業Contextを分離する。

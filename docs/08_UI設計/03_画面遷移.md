# 画面遷移

## 1. 目的

本ドキュメントは、Engineer Skill Management App のMVPにおける画面間の遷移を定義する。

`02_画面一覧.md` で定義した画面・Routeを基準として、以下を整理する。

- 認証前後の遷移
- 主要Navigation
- 機能ごとの画面遷移
- 登録・更新後の遷移
- キャンセル時の遷移
- 権限による遷移制御
- Not Found / Access Deniedへの遷移

本ドキュメントを、共通レイアウト・Navigation・個別画面UI設計の基準とする。

---

## 2. 基本方針

### 2.1 Frontend Route

画面遷移はNext.js App Routerで管理する。

Frontend Routeは、ユーザーがブラウザ上でアクセスする画面を表す。

Backend APIのRouteとは分離して扱う。

---

### 2.2 主要Navigation

認証後の主要画面への遷移は、共通App Shell内のNavigationから行う。

主要Navigationは以下を基本とする。

```text
Dashboard
    ↓
/

Employee
    ↓
/employees

Skill
    ├── /skills
    └── /skill-categories

Administration
    ↓
/access-control
```

Navigationの表示可否はRole / Permissionに応じて制御する。

---

### 2.3 登録・編集画面

登録・編集画面はSidebar等の主要Navigationへ直接配置しない。

以下のように、一覧・詳細画面から遷移する。

```text
一覧
 ├── 登録
 └── 詳細 / 編集
```

---

### 2.4 戻り先

登録・編集・詳細画面には、ユーザーが元の操作文脈へ戻れる導線を設ける。

原則として以下を基本とする。

- 登録 → 一覧
- 編集 → 詳細または一覧
- 詳細 → 一覧
- 社員スキル編集 → 社員詳細

具体的な戻り先は各機能の遷移定義で明示する。

---

## 3. 全体画面遷移

MVP全体の基本遷移は以下とする。


## 4. 認証遷移

### 4.1 未認証ユーザー

未認証ユーザーが認証必須画面へアクセスした場合は、ログイン画面へ遷移する。

```text
認証必須Route
      |
      | 未認証
      v
   /login
```

対象例:

```text
/
/employees
/employees/*
/skills
/skills/*
/skill-categories
/skill-categories/*
/access-control
/access-control/*
```

---

### 4.2 ログイン成功

ログインに成功した場合はダッシュボードへ遷移する。

```text
/login
   |
   | Login成功
   v
   /
```

---

### 4.3 ログイン失敗

ログインに失敗した場合は画面遷移せず、ログイン画面上でErrorを表示する。

```text
/login
   |
   | Login失敗
   v
/login
 + Error表示
```

---

### 4.4 認証済みユーザーのログイン画面アクセス

認証済みユーザーが `/login` へアクセスした場合は、ダッシュボードへ遷移する。

```text
/login
   |
   | 認証済み
   v
   /
```

---

### 4.5 ログアウト

ログアウト成功後はログイン画面へ遷移する。

```text
認証済み画面
      |
      | Logout
      v
   /login
```

---

## 5. Dashboard遷移

Dashboardは認証後の主要なEntry Pointとする。

```text
/
|
+--> /employees
|
+--> /skills
|
+--> /skill-categories
|
└--> /access-control
     ※権限がある場合のみ
```

Dashboardから提供する具体的な導線は、個別画面設計で定義する。

## 6. Employee画面遷移

### 6.1 基本遷移

```text
/employees
社員一覧
  |
  +--> /employees/create
  |    社員登録
  |
  +--> /employees/[employeeId]
       社員詳細
         |
         +--> /employees/[employeeId]/edit
         |    社員編集
         |
         └--> /employees/[employeeId]/skills
              社員スキル編集
```

---

### 6.2 社員一覧 → 社員登録

社員登録権限を持つユーザーは、社員一覧から社員登録画面へ遷移できる。

```text
/employees
    |
    | 社員登録
    v
/employees/create
```

権限がない場合は登録Actionを表示しないことを基本とする。

---

### 6.3 社員登録成功

登録成功後は、作成された社員の詳細画面へ遷移することを基本とする。

```text
/employees/create
        |
        | 登録成功
        v
/employees/[employeeId]
```

新規登録結果をそのまま確認できるため、一覧ではなく詳細画面を基本の遷移先とする。

---

### 6.4 社員登録キャンセル

登録をキャンセルした場合は社員一覧へ戻る。

```text
/employees/create
        |
        | Cancel
        v
/employees
```

---

### 6.5 社員一覧 → 社員詳細

一覧の対象社員を選択すると詳細画面へ遷移する。

```text
/employees
    |
    | 社員選択
    v
/employees/[employeeId]
```

---

### 6.6 社員詳細 → 社員編集

社員更新権限を持つユーザーは、社員詳細から編集画面へ遷移できる。

```text
/employees/[employeeId]
        |
        | 編集
        v
/employees/[employeeId]/edit
```

---

### 6.7 社員編集成功

社員情報の更新成功後は社員詳細へ戻る。

```text
/employees/[employeeId]/edit
        |
        | 更新成功
        v
/employees/[employeeId]
```

---

### 6.8 社員編集キャンセル

編集をキャンセルした場合も社員詳細へ戻る。

```text
/employees/[employeeId]/edit
        |
        | Cancel
        v
/employees/[employeeId]
```

---

### 6.9 社員詳細 → 社員スキル編集

社員スキル更新権限を持つユーザーは、社員詳細から社員スキル編集画面へ遷移する。

```text
/employees/[employeeId]
        |
        | スキル編集
        v
/employees/[employeeId]/skills
```

---

### 6.10 社員スキル編集完了

社員スキルの変更完了後は社員詳細へ戻る。

```text
/employees/[employeeId]/skills
        |
        | 保存成功
        v
/employees/[employeeId]
```

---

### 6.11 社員スキル編集キャンセル

キャンセルした場合も社員詳細へ戻る。

```text
/employees/[employeeId]/skills
        |
        | Cancel
        v
/employees/[employeeId]
```

## 10. 権限による遷移制御

### 10.1 Navigation表示

ユーザーが利用できない機能は、Navigationへ表示しないことを基本とする。

例:

```text
権限管理可能な管理者
        |
        v
Administration
└── Access Control
```

```text
権限管理不可
        |
        v
Administration / Access Controlを表示しない
```

---

### 10.2 Action表示

画面自体は閲覧可能だが登録・編集権限がない場合は、利用できないActionを表示しないことを基本とする。

例:

```text
社員閲覧可能
社員登録不可

/employees
  |
  +-- 社員一覧       表示
  |
  └-- 社員登録Button 非表示
```

Disabled表示の方が利用者にとって適切な場合は、個別画面設計で判断する。

---

### 10.3 権限のないRouteへ直接アクセスした場合

URLの直接入力等によって権限のない画面へアクセスした場合は、Access Deniedへ遷移する。

```text
権限のないRoute
       |
       v
/forbidden
```

Frontendによる表示制御のみを認可として扱わず、Backend側の認可結果も正とする。

---

## 11. Not Found遷移

### 11.1 存在しないRoute

存在しないFrontend Routeへアクセスした場合は、Next.jsのNot Found処理を使用する。

```text
存在しないRoute
      |
      v
Not Found
```

---

### 11.2 存在しないResource

Route自体は有効でも、対象Resourceが存在しない場合はNot Foundとして扱う。

例:

```text
/employees/[存在しないemployeeId]
             |
             v
          Not Found
```

対象例:

- Employee
- Skill
- Skill Category
- User

Backend APIからResource Not Foundが返された場合も、画面の性質に応じてNot Found表示へ変換する。

---

## 12. Validation Error時の遷移

入力Validation Errorの場合は、原則として画面遷移しない。

```text
登録 / 編集画面
      |
      | Validation Error
      v
同一画面
+ Error表示
```

ユーザーの入力内容を可能な限り維持し、対象Field付近にValidation Errorを表示する。

---

## 13. API Error時の遷移

登録・更新等で予期しないAPI Errorが発生した場合は、原則として自動的に別画面へ遷移しない。

```text
操作実行
  |
  | API Error
  v
現在の画面
+ Error Feedback
```

再試行可能な場合は、ユーザーが同じ画面から再試行できる状態を基本とする。

認証切れ・権限変更・Resource Not Found等、別の状態として扱うべきErrorについては、それぞれ対応する画面へ遷移する。

---

## 14. Breadcrumb

認証後画面では、現在位置と上位画面を把握できるようBreadcrumbを利用することを基本とする。

例:

```text
社員一覧
Employees
```

```text
社員詳細
Employees > 社員名
```

```text
社員編集
Employees > 社員名 > 編集
```

```text
社員スキル編集
Employees > 社員名 > スキル編集
```

```text
スキル登録
Skills > 登録
```

Breadcrumbの具体的な見た目・共通Componentは、共通レイアウト・共通コンポーネント設計で定義する。

---

## 15. Navigationと現在位置

Sidebar等の主要Navigationでは、現在表示している機能を識別できる状態とする。

例:

```text
/employees
/employees/create
/employees/[employeeId]
/employees/[employeeId]/edit
/employees/[employeeId]/skills
```

上記はいずれも `Employee` NavigationをActiveとして扱う。

同様に、

```text
/skills
/skills/create
/skills/[skillId]/edit
```

は `Skill` 内のスキル一覧をActiveとして扱う。

```text
/skill-categories
/skill-categories/create
/skill-categories/[skillCategoryId]/edit
```

はスキルカテゴリをActiveとして扱う。

---

## 16. ブラウザBack操作

ブラウザBack操作を阻害しない設計とする。

ただし、保存成功後など、完了済みのFormへBack操作で戻った場合に二重送信等が発生しないよう実装時に考慮する。

未保存の変更がある状態で画面を離れる際の警告については、必要性を個別画面設計で判断する。

MVPではすべてのFormへ一律に離脱警告を導入しない。

| 起点 | 操作・条件 | 遷移先 |
| --- | --- | --- |

| 認証済み画面 | Logout | `/login` |
| `/employees` | 社員登録 | `/employees/create` |
| `/employees/create` | 登録成功 | `/employees/[employeeId]` |
| `/employees/create` | Cancel | `/employees` |
| `/employees` | 社員選択 | `/employees/[employeeId]` |
| `/employees/[employeeId]` | 編集 | `/employees/[employeeId]/edit` |
| `/employees/[employeeId]/edit` | 更新成功 / Cancel | `/employees/[employeeId]` |
| `/employees/[employeeId]` | スキル編集 | `/employees/[employeeId]/skills` |
| `/employees/[employeeId]/skills` | 保存成功 / Cancel | `/employees/[employeeId]` |
| `/skills` | スキル登録 | `/skills/create` |
| `/skills/create` | 登録成功 / Cancel | `/skills` |
| `/skills` | 編集 | `/skills/[skillId]/edit` |
| `/skills/[skillId]/edit` | 更新成功 / Cancel | `/skills` |
| `/skill-categories` | 登録 | `/skill-categories/create` |
| `/skill-categories/create` | 登録成功 / Cancel | `/skill-categories` |
| `/skill-categories` | 編集 | `/skill-categories/[skillCategoryId]/edit` |
| `/skill-categories/[skillCategoryId]/edit` | 更新成功 / Cancel | `/skill-categories` |

| `/access-control/[userId]/edit` | 更新成功 / Cancel | `/access-control` |

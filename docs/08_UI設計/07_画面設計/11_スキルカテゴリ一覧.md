# スキルカテゴリ一覧

## 1. 目的

Skill Category Masterを一覧表示し、確認・登録・編集・状態変更を行うための画面とする。

スキルカテゴリ登録・スキルカテゴリ編集は独立画面ではなく、本画面上のDialogとして扱う。

Skill Categoryの無効化・再有効化は、操作の影響を確認できるよう必要に応じてAlert Dialogを利用する。

---

## 2. 対象ユーザー・権限

対象ユーザーは、Skill Category Masterの参照権限を持つ認証済みユーザーとする。

Skill Categoryの登録・編集・無効化・再有効化Actionは、それぞれ必要な権限を持つユーザーにのみ表示することを基本とする。

Frontend上の表示制御はUI制御として扱い、最終的な認可はBackendを正とする。

---

## 3. Route

```text
/skill-categories
```

とする。

スキルカテゴリ登録・編集DialogのOpen / CloseではRouteを変更しない。

以下の独立Routeは設けない。

```text
/skill-categories/create
/skill-categories/[categoryId]/edit
```

---

## 4. 画面種別

本画面はSkill Category Master管理の一覧画面とする。

以下の操作Contextを集約する。

```text
/skill-categories
├── Skill Category一覧
├── SkillCategoryCreateDialog
├── SkillCategoryEditDialog
└── Skill Category状態変更確認
```

一覧Contextを維持したまま、比較的小規模な登録・編集を行う。

---

## 5. Breadcrumb

基本形は以下とする。

```text
Skill Categories
```

Dialogを開いてもBreadcrumbは変更しない。

```text

```

例:

```text

```

---

## 8. 一覧表示項目

Skill Category一覧では、既存Skill Category Domain・API仕様に基づく情報を表示する。

主な候補:

```text
Category Name
Status
Actions
```

必要に応じて識別子等を表示してよいが、管理操作に不要な内部情報を過度に表示しない。

---

## 9. Category Name

Skill Categoryを識別する主要情報としてCategory Nameを表示する。

例:

```text
Language
Framework
OS
Middleware
Cloud
Development Tool
```

具体的な名称はSkill Category Masterを正とする。

---

## 10. Status

Skill CategoryのActive / Inactive状態を表示する。

例:

```text
有効
無効
```

StatusBadge等を利用して識別可能にする。

色だけで状態を表現せず、Text Labelを併用する。

---

## 11. Actions

各Skill Categoryに対して、権限と状態に応じたActionを提供する。

候補:

```text
編集
無効化
再有効化
```

Action数やViewportに応じて、直接ButtonまたはDropdown Menu等を利用する。

---

## 12. 一覧操作

一覧の基本フローは以下とする。

```text
/skill-categories
   |
   ├── Category登録
   |      ↓
   |  SkillCategoryCreateDialog
   |
   ├── Category編集
   |      ↓
   |  SkillCategoryEditDialog
   |
   └── 状態変更
          ↓
      Alert Dialog
```

いずれも通常は一覧Routeを維持する。

---

## 13. Skill Category登録

Page Header等に登録Actionを配置する。

例:

```text
[ スキルカテゴリ登録 ]
```

Action実行時に `SkillCategoryCreateDialog` を開く。

```text
/skill-categories
   |
   | スキルカテゴリ登録
   v
SkillCategoryCreateDialog
```

---

## 14. SkillCategoryCreateDialog

Skill Category登録DialogはFeature固有Componentとして扱う。

概念上:

```text
SkillCategoryCreateDialog
├── Dialog Header
├── Skill Category Form
└── Dialog Footer
```

具体的なForm仕様は `12_スキルカテゴリ登録.md` で定義する。

Dialog Open / CloseではRouteを変更しない。

---

## 15. Skill Category登録成功

登録成功後はDialogを閉じ、Skill Category一覧を最新状態へ更新する。

```text
/skill-categories
   |
   | SkillCategoryCreateDialog
   | 登録成功
   v
/skill-categories
```

新規Categoryが一覧上で確認できる状態とする。

---

## 16. Skill Category登録キャンセル

Cancel時はDialogを閉じる。

```text
/skill-categories
   |
   | SkillCategoryCreateDialog
   | Cancel
   v
/skill-categories
```

Route変更は発生しない。

---

Action実行時に対象Categoryを指定して `SkillCategoryEditDialog` を開く。

```text
/skill-categories
   |
   | 編集
   v
SkillCategoryEditDialog
```

## 18. SkillCategoryEditDialog

Skill Category編集DialogはFeature固有Componentとして扱う。

概念上:

```text
SkillCategoryEditDialog
```

具体的なForm仕様は `13_スキルカテゴリ編集.md` で定義する。

## 19. Skill Category編集成功

編集成功後はDialogを閉じ、一覧の対象Categoryを最新状態へ更新する。

```text
/skill-categories

   v
```

Route変更は発生しない。

---

## 20. Skill Category編集キャンセル

Cancel時はDialogを閉じる。

未保存の変更は破棄する。

一覧Contextは維持する。

---

## 21. 無効化

Skill Categoryを削除する代わりに無効化して保持する既存方針を前提とする。

無効化Actionを実行した際は、必要に応じてAlert Dialogで確認する。

例:

```text
このスキルカテゴリを無効化しますか？

Framework

無効化後は新しいスキルのカテゴリとして利用できなくなります。

[ キャンセル ] [ 無効化 ]
```

具体的な影響範囲は既存Skill Category仕様を正とする。

---

## 22. 無効化後

無効化成功後は一覧を最新状態へ更新する。

対象Categoryを一覧から完全に消すのではなく、履歴保持方針に従ってInactive状態として識別可能に表示することを基本とする。

例:

```text
Framework
無効
```

---

## 23. 再有効化

既存仕様でSkill Categoryの再有効化が可能な場合は、Inactive Categoryへ再有効化Actionを提供する。

例:

```text
[ 再有効化 ]
```

必要に応じてAlert Dialogで確認する。

```text
このスキルカテゴリを再有効化しますか？

Framework

[ キャンセル ] [ 再有効化 ]
```

---

## 24. Skill Category削除

MVPではSkill Category Masterを物理削除する操作を通常UIとして提供しないことを基本とする。

既存方針に従い、Skill Categoryは無効化して履歴を保持する。

UI側で独自にDelete Actionを追加しない。

---

## 25. Skillとの関係

Skill Category MasterとSkillを明確に分離する。

```text
Skill Category Master
    ↓
Skill分類の定義・Active状態

Skill Master
    ↓
Skill Name・Category・Active状態
```

Skill Category一覧画面ではSkill Masterを直接編集しない。

---

## 26. 利用中Category

Skillから参照されているSkill Categoryについて、無効化可能かどうかは既存Domain・API仕様を正とする。

UI側だけで無効化可否Ruleを決定しない。

Backendから無効化不可Error等が返る仕様の場合は、利用者が理由を理解できるFeedbackを表示する。

---

## 27. Inactive CategoryとSkill

Inactive Categoryを参照する既存Skillが存在する場合は、その関係を履歴として保持できる既存仕様を前提とする。

新規Skill登録・編集時のCategory候補については、Inactive Categoryを新しい選択先として利用できない仕様であれば候補から除外する。

現在参照中のInactive Categoryまで単純に見えなくしない。

---

## 28. 検索

Skill Category件数や既存API仕様に応じて、Category Nameを対象としたKeyword検索を提供してよい。

例:

```text
[ キーワード                     ] [ 検索 ]
```

MVPで検索が不要な規模・仕様である場合は、必須機能としない。

UI側だけでBackend未対応の検索機能を追加しない。

---

## 29. Status Filter

既存APIが対応する場合は、Active / Inactive Filterを提供してよい。

例:

```text
状態
[ すべて ▼ ]
```

検索・Filterが不要な場合は一覧を単純に保つ。

---

## 30. Pagination

一覧件数が多い場合はPaginationを利用する。

具体的なPage Size・Pagination方式はSkill Category一覧API仕様を正とする。

件数が少なくPagination不要な仕様である場合は導入しない。

---

## 31. Sort

Sortが既存APIで提供される場合は必要に応じてUIを提供する。

候補:

- Category Name
- Status

API側にSort仕様がない場合は、UI側だけで高度なSort機能を追加しない。

---

## 32. Loading

Skill Category一覧取得中はPage構造を維持しつつSkeleton等を表示する。

例:

```text
Page Header
Skeleton List
```

Page全体を単一Spinnerだけで置き換えることを標準としない。

---

## 33. Empty State

Skill Categoryが1件も存在しない場合はEmpty Stateを表示する。

例:

```text
スキルカテゴリが登録されていません。

[ スキルカテゴリ登録 ]
```

登録権限がない場合はActionを表示しない。

---

## 34. Search Result Empty

検索またはFilterを提供する場合、条件に一致するCategoryが存在しない状態はMaster自体が空の状態と区別する。

例:

```text
条件に一致するスキルカテゴリがありません。

検索条件を変更してください。
```

必要に応じて条件Reset Actionを提供する。

---

## 35. Error State

一覧取得に失敗した場合はErrorStateを表示する。

例:

```text
スキルカテゴリ一覧を取得できませんでした。

[ 再試行 ]
```

技術的なBackend Error Messageをそのまま表示しない。

---

## 36. Operation Error

登録・編集・無効化・再有効化等の操作に失敗した場合は、現在のContextを維持したままFeedbackを表示する。

Dialog内部で発生したValidation / API ErrorはDialogを閉じないことを基本とする。

状態変更失敗時は一覧を維持する。

---

## 37. Success Feedback

操作成功後、必要に応じて成功Feedbackを表示する。

例:

```text
スキルカテゴリを登録しました。
```

```text
スキルカテゴリを更新しました。
```

```text
スキルカテゴリを無効化しました。
```

```text
スキルカテゴリを再有効化しました。
```

具体的なNotification方式は共通UI・UI状態設計に従う。

## 41. Permission

Skill Category参照権限がない場合は、既存Access Control方針に従う。

登録権限がない場合:

```text
スキルカテゴリ登録Actionを表示しない
```

編集権限がない場合:

```text
編集Actionを表示しない
```

状態変更権限がない場合:

```text
無効化 / 再有効化Actionを表示しない
```

最終認可はBackendを正とする。

---

## 45. Accessibility

以下を基本とする。

- Page Titleを明確にする
- Table HeaderをSemanticに関連付ける
- StatusをColorだけで表現しない
- Row ActionをKeyboardで操作可能にする
- Dropdown MenuをKeyboardで操作可能にする
- 検索・Filterを提供する場合は適切なLabelを設定する
- DialogのFocus Managementを適切に行う
- Alert Dialogの操作内容を明確にする
- Dialog Close後は起動元ActionへFocusを戻す
- Loading状態をVisualだけで表現しない
- ErrorをTextで表示する

## 50. MVPで扱わないもの

現時点では以下を本画面の必須機能としない。

- Skill Categoryの物理削除
- Skill Categoryの一括登録
- Skill Categoryの一括編集
- CSV Import / Export
- Drag & Dropによる並び替え
- SkillのInline登録
- SkillのInline編集
- Category Color設定
- Category Icon設定
- Display Orderの手動設定
- 高度なAdvanced Search
- Saved Search
- DialogのURL同期

必要性が明確になった場合に別途検討する。

---

## 51. APIとの関係

Skill Category一覧・登録・編集・無効化・再有効化の仕様は既存Skill Category APIを正とする。

UI上で必要な操作が既存APIと一致しない場合は、UI側だけで仕様を追加せず、システム設計との整合を確認する。

Skillからの参照関係・状態変更制約についても既存Domain・API仕様を正とする。

---

# スキル一覧

## 1. 目的

Skill Masterを一覧表示し、検索・確認・登録・編集・状態変更を行うための画面とする。

スキル登録・スキル編集は独立画面ではなく、本画面上のDialogとして扱う。

Skillの無効化・再有効化は、操作の影響を確認できるよう必要に応じてAlert Dialogを利用する。

---

## 2. 対象ユーザー・権限

対象ユーザーは、Skill Masterの参照権限を持つ認証済みユーザーとする。

Skillの登録・編集・無効化・再有効化Actionは、それぞれ必要な権限を持つユーザーにのみ表示することを基本とする。

Frontend上の表示制御はUI制御として扱い、最終的な認可はBackendを正とする。

---

## 3. Route

```text
/skills
```

とする。

スキル登録・スキル編集DialogのOpen / CloseではRouteを変更しない。

以下の独立Routeは設けない。

```text
/skills/create
/skills/[skillId]/edit
```

---

## 4. 画面種別

本画面はSkill Master管理の一覧画面とする。

以下の操作Contextを集約する。

```text
/skills
├── Skill一覧
├── 検索・絞り込み
├── SkillCreateDialog
├── SkillEditDialog
└── Skill状態変更確認
```

一覧Contextを維持したまま、比較的小規模なSkill登録・編集を行う。

---

## 5. Breadcrumb

基本形は以下とする。

```text
Skills
```

Dialogを開いてもBreadcrumbは変更しない。

---

## 6. Page Header

基本構造:

```text
スキル一覧

[ スキル登録 ]
```

必要に応じてDescriptionを表示する。

例:

```text
社員スキルとして利用するスキルマスタを管理します。
```

---

## 7. 画面構成

基本構造は以下とする。

```text
Skill List Page
│
├── Breadcrumb
├── Page Header
│   ├── Title
│   ├── Description
│   └── Create Action
│
├── Search / Filter
│
├── Skill List
│   ├── Skill Row
│   ├── Skill Row
│   └── ...
│
└── Pagination
```

Dialog表示時も一覧画面のContextを維持する。

---

## 8. 一覧表示項目

Skill一覧では、既存Skill Domain・API仕様に基づく情報を表示する。

主な候補:

```text
Skill Name
Skill Category
Status
Actions
```

必要に応じて識別子等を表示してよいが、管理操作に不要な内部情報を過度に表示しない。

---

## 9. Skill Name

Skillを識別する主要情報としてSkill Nameを表示する。

一覧上で最も認識しやすいColumnとして扱う。

例:

```text
Laravel
PHP
PostgreSQL
Docker
```

---

## 10. Skill Category

各Skillが所属するSkill Categoryを表示する。

例:

```text
Laravel       Framework
PHP           Language
PostgreSQL    Middleware
```

具体的なCategory名はSkill Category Masterを正とする。

---

## 11. Status

SkillのActive / Inactive状態を表示する。

例:

```text
有効
無効
```

StatusBadge等を利用して識別可能にする。

色だけで状態を表現せず、Text Labelを併用する。

---

## 12. Actions

各Skillに対して、権限と状態に応じたActionを提供する。

候補:

```text
編集
無効化
再有効化
```

Action数やViewportに応じて、直接ButtonまたはDropdown Menu等を利用する。

---

## 13. 検索

Skill Name等を対象としたKeyword検索を提供する。

基本構造:

```text
[ キーワード                     ] [ 検索 ]
```

検索対象・Search Parameterは既存Skill一覧API仕様を正とする。

UI側でBackend未対応の検索条件を独自追加しない。

---

## 14. Filter

必要に応じて以下のFilterを提供する。

候補:

- Skill Category
- Active / Inactive

例:

```text
カテゴリ
[ すべて ▼ ]

状態
[ すべて ▼ ]
```

実際に提供するFilterは既存API仕様とMVP要件に従う。

---

## 15. Search / Filter配置

検索・Filterは一覧上部へ配置する。

概念上:

```text
+------------------------------------------------------+
| Keyword        | Category       | Status             |
| [          ]   | [ All ▼ ]     | [ All ▼ ]         |
|                                      [ Search ]      |
+------------------------------------------------------+
```

条件が少ない場合は過度に複雑なFilter UIにしない。

---

## 16. Reset

複数検索条件を提供する場合は、必要に応じてReset Actionを提供する。

例:

```text
[ 条件をクリア ]
```

検索条件が少なく容易に解除できる場合は必須としない。

---

## 17. 一覧操作

一覧の基本フローは以下とする。

```text
/skills
   |
   ├── Skill登録
   |      ↓
   |  SkillCreateDialog
   |
   ├── Skill編集
   |      ↓
   |  SkillEditDialog
   |
   └── 状態変更
          ↓
      Alert Dialog
```

いずれも通常は一覧Routeを維持する。

---

## 18. Skill登録

Page Header等にSkill登録Actionを配置する。

例:

```text
[ スキル登録 ]
```

Action実行時に `SkillCreateDialog` を開く。

```text
/skills
   |
   | スキル登録
   v
SkillCreateDialog
```

---

## 19. SkillCreateDialog

Skill登録DialogはFeature固有Componentとして扱う。

概念上:

```text
SkillCreateDialog
├── Dialog Header
├── Skill Form
└── Dialog Footer
```

具体的なForm仕様は `09_スキル登録.md` で定義する。

Dialog Open / CloseではRouteを変更しない。

---

## 20. Skill登録成功

Skill登録成功後はDialogを閉じ、Skill一覧を最新状態へ更新する。

```text
/skills
   |
   | SkillCreateDialog
   | 登録成功
   v
/skills
```

新規Skillが一覧上で確認できる状態とする。

---

## 21. Skill登録キャンセル

Cancel時はDialogを閉じる。

```text
/skills
   |
   | SkillCreateDialog
   | Cancel
   v
/skills
```

Route変更は発生しない。

---

## 22. Skill編集

各Skillに編集Actionを提供する。

例:

```text
[ 編集 ]
```

Action実行時に対象Skillを指定して `SkillEditDialog` を開く。

```text
/skills
   |
   | 編集
   v
SkillEditDialog
```

---

## 23. SkillEditDialog

Skill編集DialogはFeature固有Componentとして扱う。

概念上:

```text
SkillEditDialog
├── Dialog Header
├── Skill Form
└── Dialog Footer
```

具体的なForm仕様は `10_スキル編集.md` で定義する。

Dialog Open / CloseではRouteを変更しない。

---

## 24. Skill編集成功

Skill編集成功後はDialogを閉じ、一覧の対象Skillを最新状態へ更新する。

```text
/skills
   |
   | SkillEditDialog
   | 更新成功
   v
/skills
```

Route変更は発生しない。

---

## 25. Skill編集キャンセル

Cancel時はDialogを閉じる。

未保存の変更は破棄する。

一覧Contextは維持する。

---

## 26. 無効化

Skillを削除する代わりに無効化して保持する既存方針を前提とする。

無効化Actionを実行した際は、必要に応じてAlert Dialogで確認する。

例:

```text
このスキルを無効化しますか？

Laravel

無効化後は新しい社員スキルの登録対象として利用できなくなります。

[ キャンセル ] [ 無効化 ]
```

具体的な影響範囲は既存Skill仕様を正とする。

---

## 27. 無効化後

無効化成功後は一覧を最新状態へ更新する。

対象Skillを一覧から完全に消すのではなく、履歴保持方針に従ってInactive状態として識別可能に表示することを基本とする。

例:

```text
Laravel
Framework
無効
```

---

## 28. 再有効化

既存仕様でSkillの再有効化が可能な場合は、Inactive Skillへ再有効化Actionを提供する。

例:

```text
[ 再有効化 ]
```

必要に応じてAlert Dialogで確認する。

```text
このスキルを再有効化しますか？

Laravel

[ キャンセル ] [ 再有効化 ]
```

---

## 29. Skill削除

MVPではSkill Masterを物理削除する操作を通常UIとして提供しないことを基本とする。

既存方針に従い、Skillは無効化して履歴を保持する。

UI側で独自にDelete Actionを追加しない。

---

## 30. EmployeeSkillとの関係

Skill MasterとEmployeeSkillを明確に分離する。

```text
Skill Master
    ↓
Skill定義・Category・Active状態

EmployeeSkill
    ↓
EmployeeとSkillの関連・Level・経験情報
```

Skill一覧画面ではEmployeeSkillを直接編集しない。

---

## 31. 利用中Skill

EmployeeSkillから参照されているSkillについても、既存仕様に従って無効化可能かどうかを判断する。

UI側だけで無効化可否Ruleを決定しない。

Backendから無効化不可Error等が返る仕様の場合は、利用者が理由を理解できるFeedbackを表示する。

---

## 32. Skill Categoryとの関係

Skill Categoryは本画面では参照・選択対象として扱う。

Skill Category Master自体の登録・編集は以下で行う。

```text
/skill-categories
```

Skill一覧からSkill CategoryをInline編集しない。

---

## 33. Pagination

一覧件数が多い場合はPaginationを利用する。

具体的なPage Size・Pagination方式はSkill一覧API仕様を正とする。

UI側で独自のPagination Ruleを追加しない。

---

## 34. Sort

Sortが既存APIで提供される場合は必要に応じてUIを提供する。

例:

- Skill Name
- Skill Category
- Status

MVPでAPI側にSort仕様がない場合は、UI側だけで高度なSort機能を追加しない。

---

## 35. Loading

Skill一覧取得中はPage構造を維持しつつSkeleton等を表示する。

例:

```text
Page Header
Search / Filter
Skeleton List
```

Page全体を単一Spinnerだけで置き換えることを標準としない。

---

## 36. Empty State

Skillが1件も存在しない場合はEmpty Stateを表示する。

例:

```text
スキルが登録されていません。

[ スキル登録 ]
```

登録権限がない場合はActionを表示しない。

---

## 37. Search Result Empty

検索条件に一致するSkillが存在しない場合は、Master自体が空の状態と区別する。

例:

```text
条件に一致するスキルがありません。

検索条件を変更してください。
```

必要に応じて条件Reset Actionを提供する。

---

## 38. Error State

一覧取得に失敗した場合はErrorStateを表示する。

例:

```text
スキル一覧を取得できませんでした。

[ 再試行 ]
```

技術的なBackend Error Messageをそのまま表示しない。

---

## 39. Operation Error

登録・編集・無効化・再有効化等の操作に失敗した場合は、現在のContextを維持したままFeedbackを表示する。

Dialog内部で発生したValidation / API ErrorはDialogを閉じないことを基本とする。

状態変更失敗時は一覧を維持する。

---

## 40. Success Feedback

操作成功後、必要に応じて成功Feedbackを表示する。

例:

```text
スキルを登録しました。
```

```text
スキルを更新しました。
```

```text
スキルを無効化しました。
```

```text
スキルを再有効化しました。
```

具体的なNotification方式は共通UI・UI状態設計に従う。

## 44. Permission

Skill参照権限がない場合は、既存Access Control方針に従う。

登録権限がない場合:

```text
スキル登録Actionを表示しない
```

編集権限がない場合:

```text
編集Actionを表示しない
```

状態変更権限がない場合:

```text
無効化 / 再有効化Actionを表示しない
```

最終認可はBackendを正とする。

## 48. Accessibility

以下を基本とする。

- Page Titleを明確にする
- Search InputへLabelまたはAccessible Nameを設定する
- Filter Controlの意味を認識可能にする
- Table HeaderをSemanticに関連付ける
- StatusをColorだけで表現しない
- Row ActionをKeyboardで操作可能にする
- Dropdown MenuをKeyboardで操作可能にする
- DialogのFocus Managementを適切に行う
- Alert Dialogの操作内容を明確にする
- Dialog Close後は起動元ActionへFocusを戻す
- Loading状態をVisualだけで表現しない
- ErrorをTextで表示する

同名SkillがDomain上許可されるかどうかは既存仕様を正とし、必要な場合は追加情報によって識別可能にする。

## 53. MVPで扱わないもの

現時点では以下を本画面の必須機能としない。

- Skillの物理削除
- Skillの一括登録
- Skillの一括編集
- CSV Import / Export
- Drag & Dropによる並び替え
- Skill CategoryのInline登録
- Skill CategoryのInline編集
- EmployeeSkillの編集
- 高度なAdvanced Search
- Saved Search
- DialogのURL同期

必要性が明確になった場合に別途検討する。

---

## 54. APIとの関係

Skill一覧・検索・登録・編集・無効化・再有効化の仕様は既存Skill APIを正とする。

UI上で必要な操作が既存APIと一致しない場合は、UI側だけで仕様を追加せず、システム設計との整合を確認する。

Skill Category選択肢についても既存Skill Category API仕様を正とする。

---

## 55. 本画面で定義しないもの

以下は既存仕様またはFrontend実装の責務とする。

- Skill API Endpoint
- Request / Responseの具体型
- Search Parameterの具体名
- Pagination実装
- Sort実装
- Form Library
- State管理方式
- Server / Client Component境界
- React Component分割
- API Client実装
- Query Cache更新方式
- Dialog Stateの具体実装
- Tailwind CSS Class
- Design Tokenの具体値

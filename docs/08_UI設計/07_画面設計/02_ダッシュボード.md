# ダッシュボード

## 1. 目的

Engineer Skill Management App にログインしたユーザーが、組織内のスキル管理状況を概要として確認し、主要機能へ素早く遷移できる画面とする。

ダッシュボードでは詳細な分析機能を提供するのではなく、MVPで必要な主要情報の概要と導線を提供することを目的とする。

---

## 2. 対象ユーザー・権限

対象ユーザーは認証済みユーザーとする。

表示する情報や操作はRole / Permissionに応じて制御する。

利用できない管理機能へのActionは表示しない。

Frontend上の表示制御はUI制御として扱い、最終的な認可はBackendを正とする。

---

## 3. Route

```text
/
```

認証後の主要Entry Pointとする。

ログイン成功後は本画面へ遷移する。

---

## 4. 画面構成

ダッシュボードは認証後共通のApp Shell内で表示する。

基本構造は以下とする。

```text
App Shell
├── Header
├── Sidebar
└── Main Content
    ├── Page Header
    └── Dashboard Content
        ├── Summary
        ├── Skill Overview
        └── Quick Actions
```

DashboardではBreadcrumbを省略可能とする。

---

## 5. Page Header

### 5.1 Title

```text
ダッシュボード
```

を基本とする。

### 5.2 Description

必要に応じて、現在の情報概要を確認できる画面であることを簡潔に示す。

例:

```text
社員・スキル情報の概要を確認できます。
```

Descriptionは必須としない。

---

## 6. 集計対象

ダッシュボードの集計対象は在籍社員のみを基本とする。

退職社員は保持対象であっても、通常のDashboard集計には含めない。

集計対象の具体的な条件は、既存のDashboard API・Domain仕様を正とする。

---

## 7. Summary

MVPでは、Application全体の状況を把握するためのSummaryを表示する。

基本候補は以下とする。

- 在籍社員数
- 登録スキル数
- スキルカテゴリ数

表示可能なAPI・要件が存在するもののみ採用する。

UI設計だけを理由として新しい集計APIを追加しない。

---

## 8. Summary Card

SummaryはCard形式を基本候補とする。

例:

```text
+----------------------+
| 在籍社員             |
|                      |
| 128                  |
+----------------------+

+----------------------+
| スキル               |
|                      |
| 64                   |
+----------------------+

+----------------------+
| スキルカテゴリ       |
|                      |
| 8                    |
+----------------------+
```

各Cardは以下の構造を基本とする。

```text
Summary Card
├── Label
├── Value
└── Optional Supporting Information
```

過度な装飾やChartを追加しない。

---

## 9. Skill Overview

MVPで取得可能な情報を利用し、スキル情報の概要を確認できる領域を設ける。

候補として以下を検討する。

- スキルカテゴリごとの登録状況
- よく登録されているスキル
- スキルレベルの分布
- 実務経験あり / 未経験の概要

ただし、既存要件・Dashboard APIで提供されていない集計をUI要件だけで追加しない。

実際に表示する内容は、既存Dashboard APIとの整合を確認して確定する。

---

## 10. Quick Actions

主要機能への導線を表示してよい。

候補:

- 社員一覧
- スキル一覧
- スキルカテゴリ一覧
- アクセス制御

権限によって利用できない機能は表示しない。

例:

```text
Quick Actions

[ 社員一覧を見る ]
[ スキル一覧を見る ]
[ スキルカテゴリを見る ]
```

権限管理可能な管理者の場合のみ、

```text
[ アクセス制御 ]
```

を追加できる。

---

---

## 13. UI状態

### 13.1 Default

取得済みのDashboard情報を通常表示する。

---

### 13.2 Loading

Dashboard情報取得中は、Page Header等の共通構造を維持する。

Summary等のData領域ではSkeletonを基本候補とする。

例:

```text
ダッシュボード

+----------------------+
| ███████              |
| ███████████          |
+----------------------+
```

画面全体を単一Spinnerだけへ置き換えない。

---

### 13.3 Partial Loading

Dashboardで複数の情報を個別取得する場合は、全Widgetの完了を待たず、それぞれの領域単位でLoading表示できる構成を許可する。

ただし、MVPで不要な複雑な非同期取得構成は避ける。

---

### 13.4 Empty

集計対象となるデータが存在しない場合は、空のCardやTableだけを表示しない。

例:

```text
登録されている社員がありません。

社員を登録すると、ここに概要が表示されます。
```

ユーザーに社員登録権限がある場合のみ、必要に応じて登録Actionを表示する。

---

### 13.5 Error

Dashboard情報取得に失敗した場合は、Application Navigationを維持したままErrorを表示する。

```text
ダッシュボード情報を取得できませんでした。

[ 再試行 ]
```

再試行可能な場合のみRetry Actionを表示する。

---

## 14. Responsive

### 14.1 Desktop

Summary Card等を複数Columnで表示可能とする。

例:

```text
+-----------+ +-----------+ +-----------+
| Employees | | Skills    | | Categories|
+-----------+ +-----------+ +-----------+

+---------------------------------------+
| Skill Overview                        |
+---------------------------------------+
```

Dashboard Contentは利用可能な横幅を活用する。

---

### 14.2 Tablet

画面幅に応じてSummary CardのColumn数を減らす。

例:

```text
+-----------+ +-----------+
| Employees | | Skills    |
+-----------+ +-----------+

+-----------+
| Categories|
+-----------+
```

---

### 14.3 Mobile

1 Columnを基本とする。

```text
ダッシュボード

+--------------------------+
| 在籍社員                 |
+--------------------------+

+--------------------------+
| スキル                   |
+--------------------------+

+--------------------------+
| スキルカテゴリ           |
+--------------------------+

+--------------------------+
| Quick Actions            |
+--------------------------+
```

横スクロールを前提としたDashboard Layoutは避ける。

---

## 15. Accessibility

以下を基本とする。

- Summary Valueを色だけで区別しない
- Card内の情報構造をSemanticに表現する
- Quick ActionをKeyboardで操作可能にする
- Link / Buttonの役割を適切に使い分ける
- Loading状態をVisualだけに依存させない
- Error MessageをTextで表示する
- Focus状態を視認可能にする
- Iconを利用する場合もText情報を維持する

## 17. MVPで扱わないもの

現時点では以下をDashboardの必須機能としない。

- 高度な分析Chart
- 時系列Trend
- 個人別Ranking
- Skill Ranking
- Customizable Widget
- Drag & DropによるWidget配置
- Dashboard Layout保存
- Export
- Real-time更新

必要性が明確になった場合に別途検討する。

---

## 18. APIとの関係

Dashboardに表示する情報は、既存のDashboard APIで提供される情報を基本とする。

UI設計側で新しい集計値を必要とする場合は、既存のシステム設計・API仕様との整合性を確認する。

UI都合のみでBackend APIを暗黙的に追加しない。

---

## 19. 本画面で定義しないもの

以下は既存仕様または後続実装の責務とする。

- Dashboard APIの具体的なEndpoint
- 集計Queryの実装
- React Component構造
- Server / Client Component境界
- API取得方式
- Cache戦略
- Tailwind CSS Class
- Design Tokenの具体値

# 画面一覧

## 1. 目的

本ドキュメントは、Engineer Skill Management App のMVPで必要となる画面・主要UI単位を定義する。

各画面・主要UIについて、以下を整理する。

- 画面ID / UI ID
- 画面名 / UI名
- Route
- 認証要否
- 目的
- 対象ユーザー
- 主な表示内容
- 主な操作
- 独立画面かDialog等のUI単位か

本ドキュメントで定義した画面・主要UI一覧を、画面遷移・共通レイアウト・個別画面設計の基準とする。

---

# 2. 基本方針

## 2.1 Frontend Route

FrontendのRouteはNext.js App Routerで管理する。

本ドキュメントでは、ユーザーがブラウザ上でアクセスするFrontend Routeを定義する。

Backend APIのRouteとは分離して扱う。

---

## 2.2 独立画面とDialog

すべての登録・編集操作に独立Routeを設けるとは限らない。

元画面のContextを維持したまま完結できる比較的小規模な操作についてはDialogとして扱う。

一方、以下のような操作は独立画面を基本とする。

- 情報量が多い
- 複数Sectionを扱う
- 複数Resourceを操作する
- 独立した作業Contextが必要
- 権限変更等、内容・影響を十分に確認しながら操作する必要がある

具体的なDialog Layout・Component設計は以下で定義する。

- `04_共通レイアウト.md`
- `06_共通コンポーネント.md`

Feature固有の詳細は `07_画面設計` で定義する。

---

## 2.3 認証

認証が必要な画面は、未認証状態ではアクセスできない。

未認証状態で認証必須画面へアクセスした場合はログイン画面へ遷移する。

ログアウトは独立画面として扱わず、認証後App ShellのUser Menu等から実行する共通Actionとして扱う。

認証状態は既存認証仕様を正とする。

---

## 2.4 権限

画面・操作の表示可否は既存Role / Permission仕様に従う。

MVPで利用するRoleは以下を前提とする。

- 管理者
- マネージャー
- サブマネージャー
- チームリーダー

一般社員RoleはMVPでは利用しない。

Frontend上の表示制御はUI制御として扱い、最終的な認可はBackendを正とする。

---

# 3. 画面分類

MVPの画面・主要UIを以下の機能単位に分類する。

```text
認証
├── ログイン
└── ログアウト（共通Action）

ダッシュボード
└── ダッシュボード

社員管理
├── 社員一覧
│   └── 社員登録Dialog
├── 社員詳細
│   └── 社員編集Dialog
└── 社員スキル編集

スキル管理
└── スキル一覧
    ├── スキル登録Dialog
    └── スキル編集Dialog

スキルカテゴリ管理
└── スキルカテゴリ一覧
    ├── スキルカテゴリ登録Dialog
    └── スキルカテゴリ編集Dialog

アクセス制御
├── ユーザー・権限一覧
└── ユーザー権限編集

共通
├── Access Denied
└── Not Found
```

# 5. 認証

## 5.1 AUTH-001 ログイン

### Route

```text
/login
```

### 目的

ユーザーを認証し、Engineer Skill Management Appへアクセス可能な状態にする。

### 対象ユーザー

未認証ユーザー。

### 主な表示内容

- Application識別情報
- Login Form
- Validation Error
- 認証Error

### 主な操作

- ログイン

### 備考

認証成功後の遷移先および、認証済みユーザーが `/login` へアクセスした場合の扱いは、既存認証仕様および `03_画面遷移.md` で定義する。

---

## 5.2 ログアウト

### Route

独立Routeを持たない。

### 目的

認証済みSessionを終了し、Engineer Skill Management Appから安全にログアウトする。

### 対象ユーザー

認証済みユーザー。

### 起点

認証後App ShellのUser Menu等から実行する。

### 主な操作

- ログアウト

### 完了後

ログアウト完了後はログイン画面へ遷移する。

```text
Logout Action
    ↓
Session終了
    ↓
/login
```

### 備考

ログアウトは独立画面として扱わず、認証共通Actionとして扱う。

具体的なAuth.jsとの連携方法、Session破棄処理、Redirect実装は既存認証設計およびFrontend実装設計を正とする。

# 12. Navigation対象

認証後の主要Navigation候補は以下とする。

```text
Dashboard

Employee
└── 社員一覧

Skill
├── スキル一覧
└── スキルカテゴリ一覧

Administration
└── アクセス制御
```

詳細・登録・編集等は原則としてSidebarへ直接配置せず、親となる一覧・詳細等から操作する。

DialogはNavigation対象としない。

Navigation項目はRole / Permissionに応じて制御する。

ログアウトはSidebarの主要Navigationには含めず、User Menu等の認証共通Actionとして提供する。

# 13. Routeを持たないUI / Action

MVPでは、以下のような操作を必ずしも独立画面として分離しない。

例:

- 小規模な登録Form
- 小規模な編集Form
- 削除確認
- 無効化確認
- 再有効化確認
- 単純なConfirmation
- Success Notification
- Error Notification
- ログアウト

具体的にDialog等を採用するかは、操作量・情報量・元画面との関連性・影響範囲を基準に判断する。

MVPで現在Dialogとして定義している主要UIは以下とする。

```text
社員登録Dialog
社員編集Dialog
スキル登録Dialog
スキル編集Dialog
スキルカテゴリ登録Dialog
スキルカテゴリ編集Dialog
```

削除・無効化・再有効化等の重要操作の確認にはAlert Dialogを利用候補とする。

ログアウトはDialogを必須とせず、User Menu等から実行する共通Actionとして扱う。

詳細な共通ルールは以下を参照する。

- `04_共通レイアウト.md`
- `06_共通コンポーネント.md`
